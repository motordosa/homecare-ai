# HomeCare AI 데모

환자용 모바일 웹과 의료진용 데스크톱 웹이 하나의 SQLite DB를 공유합니다. 현재 소스 버전은 **v0.7.0**이며 합성자료 데모 또는 별도로 설정한 카카오 인증 모드에서 식사·복약·활동·수면을 기록합니다. 의료진은 허용된 직무·환자 범위에서 기록, 업무, 기술통계와 문헌 근거를 검토합니다. 현재 제작 기준은 [개발 문서 색인](docs/README.md), 이번 변경 범위는 [실행계획](docs/USABILITY_IMPLEMENTATION_PLAN.md), 검증 결과와 남은 작업은 [실행 결과 보고서](docs/USABILITY_IMPLEMENTATION_REPORT.md)에 있습니다. 공개 사이트에 반영된 버전은 별도로 확인해야 합니다.

사용자가 제공한 배포 주소: [시작 화면](https://homecare-ai-demo.onrender.com) · [환자 모바일 화면](https://homecare-ai-demo.onrender.com/patient?patientId=p001) · [의료진 데스크톱 화면](https://homecare-ai-demo.onrender.com/clinician?patientId=p001). 무료 서버의 데이터 보존 조건과 점검 방법은 [배포 안내](DEPLOY_RENDER.md)에 있습니다.

새 버전 반영 후 [직접 사용·인수 확인 순서](docs/DEMO_ACCEPTANCE.md)로 메뉴, 약별 복약, 사진 분석과 iPhone 우선 건강 연결을 차례로 확인할 수 있습니다.

## 실행

Node.js **24.x**가 필요합니다. 런타임 외의 설치 의존성은 없습니다.

```bash
node --version
npm start
```

기본 포트는 `3000`이며 `0.0.0.0`에 바인딩합니다. `PORT`와 `DATA_DIR`로 변경할 수 있습니다. `.env` 파일은 자동으로 읽지 않으므로 환경 변수로 주입하거나 `node --env-file=.env server.mjs`를 사용하세요.

| 경로 | 용도 |
|---|---|
| `/` | 환자·의료진 체험 시작 화면 |
| `/patient` | 환자용 모바일 웹 |
| `/patient?patientId=p001` | 특정 가상 환자로 열기 |
| `/clinician` | 의료진 대시보드 |
| `/clinician?patientId=p001` | 특정 환자의 기록 확인 |
| `/api/health` | DB·기록 수·상태 확인 |
| `/api/export.csv` | 일일 기록과 식사 데이터 CSV 내보내기 |

첫 실행 시 가상 환자 6명과 최근 28일의 합성 기록을 생성합니다. 저장 위치는 기본 `data/homecare.sqlite`, `data/uploads/`이며 데이터 파일은 Git에서 제외됩니다. 같은 저장 디렉터리를 보존하면 재시작 후 기록을 다시 읽습니다. Render Free의 임시 파일시스템은 재시작·재배포 시 보존을 보장하지 않습니다.

## 체험 흐름

1. 환자용 화면에서 가상 환자를 선택합니다.
2. 식사 기록에서 음식 유형·실제 섭취량을 직접 고릅니다. 사진은 선택 사항이며, 양을 모르면 ‘모르겠어요’, 먹지 않았으면 ‘안 먹었어요’를 구별합니다. AI가 설정돼 있으면 외부전송 동의와 초안 확인 후 저장합니다.
3. 시간별 복약 목록의 회차·상태를 확인하고 활동·수면을 입력합니다. 새 입력에 정상·복용·전체 섭취를 자동 선택하지 않습니다. 저장한 대상·날짜·항목은 완료 안내에 남습니다.
4. 의료진용 화면에서 같은 환자와 기간을 선택해 기록·출처·관측수·누락을 확인합니다. 업무 목록에서는 담당자·상태·사진 검토·정정 요청을 관리합니다.
5. 연구 분석에서는 대상·기간·출처를 미리 확인하고 자료를 동결해 가명으로 반출합니다. 문헌 검토에서는 환자 개인정보가 없는 검색어를 직접 입력하고 출처·검토 근거를 보관합니다. 문헌 제공자 연결 상태는 별도 확인이 필요합니다.

기존 개요의 복약 점수는 **일일 자기보고**입니다. 새 약별 일정·회차는 **복약 계획/복약 기록**에서 별도로 확인합니다. 레거시 참고 메모에서 약과 용량을 자동 생성하지 않습니다.

사진 분석은 서버 키와 활성화 설정이 모두 필요합니다. 새 Render Blueprint는 활성화 flag와 모델을 지정하며 기존 서비스에는 Environment에서 직접 설정해야 합니다. 서버에 `HOMECARE_VISION_API_KEY`, `VISION_ENABLED=true`, `VISION_MODEL=gpt-4.1-mini`를 설정해야 합니다. 키를 브라우저나 Git에 넣지 마세요. `/api/capabilities`와 의료진의 데모 설정 화면에서 준비 상태를 확인할 수 있습니다. `npm run ai:check`는 사진 없이 모델 API 접근을 검사하고, `-- --image /path/meal.jpg`를 추가하면 선택 사진의 실제 유료 추론을 검사합니다. [GPT 활성화 안내](docs/GPT_ACTIVATION.md)를 따릅니다. 외부 전송 동의 후 사진을 분석하고, 환자의 섭취 확인 또는 의료진 대조를 거친 뒤 저장합니다. API 비용은 무료 Render 호스팅과 별개이며 현재 실제 제공자 정확도 검증을 마쳤다는 뜻이 아닙니다.

## 데이터 초기화

의료진 화면의 **데모 설정**에서 확인 문구를 입력한 뒤 실행할 수 있습니다.

- **샘플 데이터로 복원:** 기존 입력과 업로드를 지우고 6명의 합성 기록을 다시 생성합니다.
- **모든 데이터 비우기:** 환자·일일 기록·식사·업로드를 지우고 빈 스키마만 남깁니다. 재시작해도 자동으로 샘플을 넣지 않습니다. 이후 환자 추가로 새 테스트를 시작할 수 있습니다.

CLI에서는 다음을 사용합니다. 실행 중인 서버와 다른 `DATA_DIR`를 지정하지 않도록 확인하세요.

```bash
npm run db:reset -- --confirm=RESET
npm run db:reset -- --empty --confirm=RESET
```

초기화는 되돌릴 수 없습니다. 보관할 테스트 결과는 필요한 범위로 먼저 내보내고, 복원이 필요하면 DB·업로드의 별도 백업을 준비하세요. CSV는 업무·문헌·감사 이력까지 복원하는 백업이 아닙니다. 초기화는 새 업무·연구·문헌 데모 자료도 제거합니다. 전체 배포본을 비우려면 해당 배포 환경의 저장 볼륨에서도 같은 초기화를 수행해야 합니다.

## 데모 분석의 의미

- 걸음수·수면은 **직접 입력과 연결부 전송을 구별**합니다. 직접 입력값이 있으면 우선하고, 없으면 선택한 연결의 집계를 표시합니다. 폰/워치의 자동 수집은 네이티브 권한/실기기 검증 전까지 완료로 표시하지 않습니다.
- 식사사진은 실제로 업로드·저장됩니다. 수동 경로는 **선택한 음식 유형과 섭취 비율**의 고정 표, AI 경로는 **실제 제공자 분석 초안과 섭취 확인**의 추정입니다. 영양량과 복용 여부의 임상 검증 기능이 아닙니다.
- 브리핑과 확인 우선순위는 저장된 기록을 집계한 데모 규칙입니다. 검증된 진단·낙상 확률·처방 권고가 아닙니다.
- 누락과 실제 0을 구별합니다. 식사량 모름은 영양량도 null이며, 알려진 식사만 합계에 포함하고 양 미상 건수를 표시합니다. 기록된 식사 합계는 하루 전체 섭취량이 아닙니다. ‘선택 기간 기록일 비율’은 연구 프로토콜의 완결률이 아닙니다.
- 지원 인력의 자료 정리와 임상 검토·정정 승인을 구별합니다. 보호자 위임 계획 저장은 실제 보호자 로그인이나 대리 입력 권한을 활성화하지 않습니다.
- 연구 스냅샷은 선택 조건·분모·가명 자료·입력 해시·생성 정보를 보존합니다. 통계 해석이나 임상 성능 검증을 자동으로 완료하지 않습니다. 문헌은 실제 제공자 식별자와 확보한 초록 범위를 보존하고 사람의 검토 근거를 기록합니다.
- AUTH_MODE=demo는 로그인 없는 공동 체험이고 AUTH_MODE=kakao는 로그인·본인 환자 범위를 검사합니다. 실제 환자 정보는 입력하지 마세요. 연구에 사용하기 전 동의·기관별 권한 분리·기관 보안과 연구 프로토콜에 맞는 기능을 별도 완성해야 합니다. DB 초기화만으로 연구 환경이 완성되지는 않습니다.

## 테스트

```bash
npm test
```

테스트는 임시 DB를 사용하며 실행 중인 데모 DB를 수정하지 않습니다. 실제 이미지 저장·조회, 기록 변경, 환자 분리, 입력 검증, CSV, 재시작 후 보존, 초기화 후 빈 상태 유지와 샘플 복원을 확인합니다.

모바일 입력→의료진 조회와 초기화까지 브라우저로 검증하려면 개발 의존성을 설치합니다.

```bash
npm ci --ignore-scripts
npm run test:browser
npm run test:automation
npm run test:auth
npm run test:medication-photo
npm run test:usability
```

브라우저 테스트는 시스템 Chromium(`/usr/bin/chromium`)을 우선 사용합니다. 다른 위치는 `CHROMIUM_PATH`로 지정할 수 있으며, Chromium이 없으면 `npx playwright install chromium`으로 준비하세요. 테스트는 격리 DB와 임시 서버를 만들고 종료하며, 화면 캡처는 `test-results/`에 저장합니다.

자동화 브라우저 테스트의 AI·문헌 제공자 응답은 fixture이며 실제 외부 서비스 호출 성공이나 정확도 검증이 아닙니다. `test:usability`는 변경된 환자·의료진 동작을 격리 서버와 합성자료로 검사합니다. 실제 실행 결과·제약은 실행 결과 보고서를 확인하세요. Android 원본 Java 핵심 검사는 연결 앱 README를 따르고, APK/실기기 완료와 구별합니다.

기획과 계약을 먼저 검토한 뒤 변수 목록을 갱신합니다. CI는 오래된 변수 목록을 실패 처리합니다.

```bash
npm run docs:variables
npm run docs:check
```

공개 배포본을 변경 없이 점검하려면 다음 명령을 사용합니다. GET 요청만 사용해 화면·API·CSV·정적 파일 일치를 확인하며, 빈 DB도 정상으로 처리합니다. 결과는 `test-results/deployment/`에 저장합니다. 환자 입력·사진 저장 검증은 별도로 수행해야 합니다.

```bash
npm run demo:check -- https://homecare-ai-demo.onrender.com
```

## 컨테이너 실행·배포

**무료 외부 테스트 배포는 Render Free로 준비되어 있습니다.** [무료 배포 안내](DEPLOY_RENDER.md)의 링크에서 계정을 연결하고 Blueprint를 생성하면 됩니다. `render.yaml`은 무료 Docker 서비스 하나와 임시 SQLite 저장소만 사용합니다. 무료 서버에서는 재시작·재배포 시 테스트 DB·사진이 초기화될 수 있습니다. 아래 영구 볼륨 방식과 데이터 보존 조건이 다릅니다.

```bash
docker compose up --build -d
docker compose ps
```

Compose는 `homecare-data` 볼륨을 `/app/data`에 연결합니다. 컨테이너 재생성 후에도 DB·사진을 보존합니다. 서비스는 `3000` 포트입니다. 외부 배포는 Node 24 또는 Docker를 지원하는 호스팅에서 실행하고 **영구 볼륨을 `/app/data`에 연결**하세요. SQLite를 사용하는 이 데모는 단일 인스턴스로 운영합니다.

```bash
docker build -t homecare-ai-demo .
docker run -d --name homecare-ai-demo -p 3000:3000 \
  -v homecare-demo-data:/app/data homecare-ai-demo
```

설치 경로에 의존하지 않는 Dockerfile·Compose 구성과 상태 확인 엔드포인트를 제공합니다. 현재 환경의 실행·컨테이너 검증은 공개 인터넷 배포와 별개입니다. 소스를 푸시한 뒤 Render에서 수동 배포를 완료해야 변경이 실제 서버에 반영됩니다.

네트워크가 허용되는 환경의 일시적 체험 주소는 공식 Cloudflare Quick Tunnel을 사용할 수 있습니다.

```bash
cloudflared tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:3000
```

이는 임시 주소이며 앱·터널 프로세스가 살아 있어야 합니다. Quick Tunnel 생성 API와 edge TCP 7844 접근이 필요합니다. 상시 배포에는 영구 볼륨을 갖춘 호스팅과 HTTPS 구성을 사용하세요.

## 외부 활성화와 기존 기능의 도입 이력

아래 버전 표시는 각 기능이 처음 추가된 시점입니다. 현재 화면 규약은 [SCREEN_SPEC.md](docs/SCREEN_SPEC.md)의 v0.7.0 기준을 사용하며, 이전 메뉴 개수나 입력 보호 범위를 현재 규약으로 적용하지 않습니다.

### v0.6 카카오 로그인·공지·개별 메시지

[활성화 안내](docs/KAKAO_SETUP.md)를 먼저 따릅니다. `/login`에서 시작하고, 의료진은 공지 관리 및 환자 메시지 메뉴를 사용합니다. 환자는 상단 공지와 하단 메시지에서 확인·답장합니다. 메시지는 사이트 안에 저장되며 카카오톡으로 발송하지 않습니다. 실제 카카오 앱 키와 의료진 계정 등록이 필요합니다. 설정이 없는 실제 인증 모드는 잠기며 데모로 자동 전환하지 않습니다.

관련 검증 명령은 `npm run test:auth`이며 카카오 모의 응답 검사와 실제 제공자·Render 활성화 결과를 구별합니다. 직무별 서버 권한·배정 범위는 v0.7.0 실행계획의 `STAFF_ACCESS_JSON` 계약을 함께 확인하세요.


### v0.6.1 약봉투 사진 복약 데모

의료진이 등록한 약별 계획이 있으면 환자 복약 → **약봉투 사진으로 기록**에서 설정된 GPT로 포장 글자를 읽고 회차·상태를 직접 확인해 사진과 함께 저장합니다. 의료진 복약 화면에서 원본/당시 자기보고/OCR 후보를 확인하고, v0.7.0 업무 목록에서 권한에 따라 검토 상태를 관리합니다. 사진은 복용 증거가 아니며 낱알 외형 식별·국내 약품 API는 후속입니다. 기존 사진 AI 키를 사용합니다. [제작 규약](docs/MEDICATION_PHOTO_DEMO_SPEC.md), [배포 후 확인 절차](docs/USER_ACTION_REPORT.md#u-05-빠른-약봉투-사진-데모-v061-확인). 로컬 브라우저 검증은 `npm run test:medication-photo`이며 실제 API 과금 없이 임시 DB·mock 제공자를 사용합니다.

v0.7.0 문헌 기능의 상세 화면·검색·검토 계약은 [EVIDENCE_WORKSPACE_SPEC.md](docs/EVIDENCE_WORKSPACE_SPEC.md)를 따릅니다. 이번 로컬 구현·모의 검증과 공개 Render 반영, 실제 고령자 평가, 문헌·GPT·카카오·건강기기의 실제 연결 결과는 각각 구별해 보고합니다.
