# 의료진 설정형 자동 음성 안내 구현·검증 보고

2026-10-25 KST, 개발 버전 **0.9.0 / schema9**. 사용자 요구를 CVG-01~06으로 정리하고 [제작 계약](CONTEXTUAL_VOICE_GUIDANCE_SPEC.md)과 화면·API·자료 사전을 먼저 수정한 뒤 구현했다. 기존 모바일 웹·의료진 데스크톱 구조, 환자 기록 API와 음성 입력을 유지했다.

## 사용 방법과 변경 결과

의료진 화면의 **음성 안내 설정**에서 ‘공통 기본’ 또는 ‘선택 환자만’을 고른다. 각 안내를 펼쳐 문구·발생 동작·시간·요일·적용 날짜·기록 조건·반복 기준·간격·하루 상한·우선순위·입력값 확인 기준을 설정하고 **설정 저장**한다. 환자별 설정을 없애려면 **공통 설정 따르기**를 사용한다. 권한이 없는 보조 인력에게는 조회만 제공하며 담당 환자 범위를 서버에서 검사한다. 의료진 기기의 미리듣기는 환자의 재생 횟수에 포함하지 않는다.

기본 한국어 안내 11개를 제공한다. 오전06~12시·오후12~18시·저녁18~22시 첫 홈 진입 안내 3개, 식사·복약·약 사진·걸음·수면·건강 기록 진입 안내 6개, 걸음·수면 입력값 확인 2개다. 실제 최신 기록에 맞는 조건을 검사하며 각 일반 안내는 기본 하루1회다.22~06시는 정기 인사가 없고 직접 연 메뉴나 값 확인 안내는 가능하다.

환자 화면의 안내 듣기·다시 듣기·전체 듣기·목소리/속도 선택·인식 확인문 읽기 버튼을 제거했다. **이용 안내 → 음성·알림 설정 → 음성 안내 사용하기**에서 켜거나 끌 수 있고, 재생 중에는 화면·대화상자 안에서 **안내 멈춤**을 누를 수 있다. 마이크로 입력하고 글을 확인·정정·적용·저장하는 기능은 유지한다. 기존 브라우저의 끄기 선택은 아직 서버 선택이 없는 환자에 한해 보존한다.

10걸음 또는 수면10분처럼 확인 기준에 해당하면 큰 글자와 **이 값이 맞아요 / 수정하기**를 보여 준다. 확인 자체는 저장이 아니며 다음 저장 조작으로 확정한다. 낮은 값이 실제일 수 있으므로 건강 이상으로 판정하거나 강제로 보정하지 않는다. 값·날짜·폼·환자·의료진 설정이 달라지면 다시 확인한다. 기존 수면 저장 정밀도는0.1시간이므로10분은0.2시간으로 반올림하며 변환 결과를 표시한다. 음성을 꺼도 시각적 확인은 유지한다.

## 저장·반복·실패 처리

기존 DB를 삭제하지 않고 설정·변경 요청 영수증·환자 선호·재생 예약의4개 테이블을 추가했다. 공통 설정을 환자별로 상속하거나 덮을 수 있다. 수정번호 충돌과 응답 유실 후 같은 UUID의 재시도를 처리하며, 실제 환자 원기록과 음성 인식 초안을 새 재생 기록에 보관하지 않는다.

한국 시간의 환자/규칙/날짜를 기준으로 서버가 원자적으로 재생을 예약하고 실제 발화 시작 콜백에서만 시작을 기록한다. 같은 안내를 새로고침·다중 탭·서버 재시작으로 반복하지 않는다. 문구를 편집해도 같은 규칙 ID의 당일 시작 기록은 유지한다. 음성·마이크는 겹치지 않고 화면/날짜 변경·숨김·세션 종료에서 이전 안내를 취소한다. 시작/종료 콜백이 빠져도 제한 시간 후 화면 조작을 복구한다.

자동 재생이 막히면 같은 글을 남기고, 다음 일반 화면 조작 전에 서버 예약을 준비하여 그 조작 안에서 동기적으로 재생한다. 최대 두 번 시도 후에는 글만 제공한다. 목소리 목록이 늦게 준비되는 경우도 처리한다. 화면을 닫은 뒤의 예약 푸시나 백그라운드 음성은 지원하지 않는다. 새 외부 서비스·API 키·유료 음성 비용은 필요 없다.

## 검증 환경과 결과

Node24, 실제 Chromium, 별도 임시 SQLite/합성 환자에서 검증했다. HTTP·입력·저장·화면 이동은 실제이고 SpeechSynthesis/SpeechRecognition·일부 오류/시각은 명시적으로 모의했다. 공개 환자 자료를 삭제하거나 수정하지 않았다.

|---|---|
| Node 단위·API |188개: 신규 설정/권한/동시 예약/보존19개, 조건 평가5개 포함 |
| 의료진 설정 브라우저 |6개 그룹: 상세 필드·실제 저장·취소·원고 보호·1440/390px |

재현 가능한 스크립트는 package.json의 test/test:guidance/test:voice/test:reliability와 기존 회귀 명령에 포함했고 CI에 test:guidance를 추가했다. 로컬 증거는 git 제외 경로 test-results/guidance와 test-results/voice-guidance에 남겼다. 현재 커밋의 원격 CI 결과와 저장소 상태는 PR 및 최종 인계 기록으로 확인한다. 원격 자동화 검사에서 한 차례 실패가 발생해 동시 실행으로 위 검사 경합을 재현·보강했고, 후속 실패의 시나리오/스택을 GitHub 검사 주석에서도 확인할 수 있도록 진단을 추가했다.

## 완료 범위와 남은 확인

개발·로컬 검증·문서 정리를 완료하고 `codex/clinician-voice-guidance`를 푸시하여 [PR #3](https://github.com/motordosa/homecare-ai/pull/3)에 반영했다. 원격 CI 결과는 PR에서 해당 최신 SHA를 확인한다. main 병합·Render 배포는 이번 작업에서 수행하지 않았다. 공개 `/api/health` GET은2026-10-25 확인 시0.8.1/schema8이었다. 새0.9.0이 공개 반영됐다는 뜻이 아니다. 배포 시 대상 커밋 포함 여부와0.9.0/schema9를 함께 대조해야 한다.

실제 iPhone Safari의 한국어 음질, 사용자 조작 없이 허용되는 재생 범위, 스피커/무음·Bluetooth·권한·실제 마이크는 이 환경에 기기 접근 수단이 없어 미검증이다. 모의 통과를 실기기 통과로 표시하지 않는다. 기존 [마이크 인수 절차](MICROPHONE_ACCEPTANCE.md)에 더해, 아침 첫 접속·새로고침 무반복·식사 진입·값 확인·마이크 시작 시 안내 중단·끄기 유지까지 실제 기기에서 확인한다. 브라우저 제한에 따라 첫 안내가 첫 일반 터치 뒤에 들리거나 글로만 제공될 수 있다.
