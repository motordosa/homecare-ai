# 환자 화면 오류 점검·수정 전략 보고서

2026-10-25 KST · **감사 및 수정계획, 제품 수정 미실행** · 기준 `d58f2c4`, v0.8.0/schema7.

사용자 증상: **아이폰 Safari**에서 음성이 부자연스럽고 느리며, 음성 입력이 잘 되지 않고 화면이 멈추는 것으로 보인다. 이번에는 환자6메뉴와 입력 화면의 정상 사용뿐 아니라 응답 지연·유실·오류·빠른 이동·취소·부적절한 입력·음성 이벤트 누락을 점검했다. 실제 iPhone의 해당 발생 상황과 원인이 모두 확정된 것은 아니다.

## 판단

우선 수정할 문제는 **세션 요청 무제한 대기, 초기 실패 후 재시도 버튼 무반응, 음성 종료 신호 누락 시 입력 잠김**이다. 요청을 기다리는 상태와 음성 상태가 끝나지 않는 경로를 실제 로컬 브라우저에서 재현했다. 전체 JavaScript 실행이 중단되거나 Safari 프로세스가 충돌한 것으로 확인한 것은 아니다. 저장 응답 지연 시 약20초 동안 메뉴·닫기 버튼이 잠겨 고령자에게 멈춤처럼 보일 수 있다.

음성 입력의 반복 실패에는 **말을 인식하는 단계와 인식된 한국어 문장을 해석하는 단계**가 함께 영향을 준다. 일부 안내는 실제로 거부하는 말을 다시 말하라고 권하고 있으며, 자연스러운 완성 문장의 지원 범위도 좁다. 음성 출력은 첫 번째 한국어 음성과 속도0.9를 고정 사용한다. 사용자 체감과 관련 있는 구현 조건이지만 실제 음질·속도를 아이폰에서 청취한 결과는 아니다.

## 검사 범위와 증거 수준

- 이번 새 점검: **19개 검사 묶음**(공통 세션·탐색4, 음성7, 입력·저장·사진·연결8). 실제 Chromium·로컬 HTTP·임시 SQLite를 사용했다. 네트워크 장애·응답 유실·시계 진행·Web Speech 이벤트는 명시적으로 조작했다. 모의 음성 이벤트를 실제 마이크 인식 성공으로 계산하지 않았다.
- 현재 공개 서비스의 health는0.8.0/schema7이며 HTML/JS/CSS **27개 파일 전부** 검사 기준 소스와 일치한다. 이번 공개 접근은 GET뿐이며 공개 DB에 시험 입력·리셋을 하지 않았다.
- 기존 공개 점검에서 확인한 ‘일일 기록 조회 중 음성 진입 시 날짜만 표시’ 사례를 함께 반영했다. 이전 공개 공지·기록·메시지 정상 검사는 이번 장애 주입 검사를 대신하지 않는다.
- iPhone 실기기·마이크·한국어 발화 품질·Safari 프로세스 충돌은 미검증이다. WebKit 엔진도 설치를 시도했지만 배포 호스트 접근이 네트워크 정책403으로 차단되어 실행하지 못했다. Chromium에 iPhone 화면 크기를 적용하는 것을 Safari 검사라고 부르지 않는다.

## 정상 보호와 검사 한계

중지 버튼을 누르지 않은 무응답 음성 인식은 기존25초 제한으로 복구됐다. 권한 거절 후 수동 대안, 메시지 원고 보존, 저장 성공 후 목록 조회 실패 구분, 음식/섭취량 미선택과 음수 걸음 입력 차단, 닫기 취소 시 원고 보존은 통과했다. 식사 저장 결과의 초기 비교식이 목록 개수에 잘못 의존한 검사는 저장 ID 대조로 다시 확인해 통과했고 원본 증거에도 교정 위치를 표시했다.

이번 점검은 가능한 모든 브라우저·폰·조합의 완전 검증이 아니다. 특히 사용자 iPhone의 정확한 기종/iOS 버전·네트워크·실제 발화·마이크 권한·Bluetooth·잠금/복귀 조건은 아직 확보하지 못했다. 실제 사이트 프로세스 충돌, 실제 음성 공급자 장애, HEIC 자동 변환 성공을 확인했다고 보고하지 않는다.

## 수정 전략

**첫 릴리스 v0.8.1은 복구 가능성을 우선한다.** 세션/초기화, 마이크 종료/초안, 기록 조회/음성 진입, 지연/실패 안내, 이미지 검증, 연결 발급 중복을 순서대로 수정한다. 기본 음성의 OS ko 선택·속도 설정·짧은 안내·파서 문구 정합성도 같은 검증 경로로 보완한다. 현재 제안 버전이며 아직 구현/병합/배포하지 않았다.

**후속 v0.8.2는 iPhone 사용 시험에 근거해 조작 수와 음질을 개선한다.** 현재 걸음 음성 기록은 홈 진입부터 저장까지 통상8회 이상의 조작이 필요하다. 필드 자동 선택·인식 종료 후 검토 자동 표시·중복 확인 축소를 검토하되 날짜/수치/단위와 명시 저장 확인은 유지한다. ‘듣기’는 짧은 인사와 다음 행동1개를 기본으로 하고 자세한 안내는 별도 제공한다.

기기 TTS 개선으로도 음질이 충족되지 않을 때만 사람 녹음 또는 서버 TTS를 비교한다. 우선 이름·수치가 없는 공통 문구를 시험하고 비용·지연·외부 전송 범위·보관을 정한다. 기존 사진 GPT 키가 있다는 이유로 음성 외부 전송과 새 비용을 자동 활성화하지 않는다. 서버 STT/TTS를 붙이는 것만으로 UI 잠김·초안 소실·파서 오류가 해결되지는 않는다.

구현 순서·변수/상태 계약·검사 기준·버전업/배포 관문은 [세부 실행계획](PATIENT_RELIABILITY_PLAN.md)을 따른다. 현재 변경은 보고서·계획·검증 증거뿐이며 공개 서비스와 제품 코드는 v0.8.0 그대로다.
