# 환자 오류 복구 결과 · v0.8.1

2026-10-25 KST. 기준 운영본 `d58f2c4`/0.8.0/schema7에서 환자 오류를 수정했다. 개발본 목표는0.8.1/schema8, 브랜치는 `codex/patient-reliability-fixes`다. **실제 iPhone Safari 마이크 인식·소리 검증은 미완료다.** 처음에는 Draft PR로 보관했으나 이후 사용자가 최종 커밋을 배포 가능하게 준비하라고 지시해 main 병합·동일 SHA CI·배포 인계를 진행한다. 운영 본체를 바꾼 테스트나 기존 DB 초기화는 수행하지 않았다.

## 변경과 검증 대응

기획·화면·자료/상태 계약을 먼저 수정하고 아래 기능과 회귀 검사를 연결했다. 화면별 상단 X·6개 환자 메뉴·10개 의료진 메뉴와 기존 인증/부분 저장/자료 출처를 유지한다.

검토 중 추가로 발견한 문제도 반영했다: 비정상401본문이어도 인증 복구, 폐기한 연결의 같은 조건 새 발급, 확정 인식 뒤 네트워크 오류 시 첫 원고 보존, 종료된 시도의 늦은 시작 중단. 숫자 `30 50 걸음`을3050으로 합치지 않는다. 일일 `먹었어요`는 하루 모두 복용으로 임의 해석하지 않는다. 음성은 확인·적용 후 기존 저장 버튼으로만 DB에 기록한다.

연결 영수증은 schema8의 추가 테이블이며 토큰 평문을 저장하지 않는다. 기존 키 없는 발급과 네이티브 API는 호환된다. 입력·원고·미확정 요청 UUID는 RAM에만 보존하므로 강제 종료/새로고침까지 영구 보존하지 않는다. 미확정 상태에서 이탈하면 경고하며 건강 원고나 토큰을 URL/localStorage/로그에 저장하지 않는다.

## 검증 환경과 실행

Node24, Linux Chromium, 임시 HTTP 서버/SQLite로 실제 클릭·저장·조회·재시도·새로고침을 검사했다. 브라우저 시계와 네트워크 오류 주입은 명시한 테스트 조건이다. 음성 제공자·권한 이벤트·발화는 모의이며 실제 마이크/음질 검사 결과가 아니다. AI와 건강 기기 회귀의 제공자도 fixture다.

정식 실행: `npm test`, `npm run test:reliability`, `npm run test:voice`, `npm run test:browser`, `test:automation`, `test:auth`, `test:medication-photo`, `test:usability`, `test:menus`, `test:workspaces`, `docs:variables`, `docs:check`, `git diff --check`. 통과 수와 저장소/CI 상태는 아래 완료 기록에서 구분한다. 검사 실패를 숨기지 않고 계약 변경으로 달라진 테스트 기대값과 실제 결함을 구별해 재실행한다.

새 검사 원본은 `test/client-io-reliability-browser.mjs`, `dictation-reliability-browser.mjs`, `speech-reliability-browser.mjs`, `patient-reliability-browser.mjs`, `health-connection-issuance.test.mjs`와 기존 파서/메뉴 회귀에 있다. 실행 증거 JSON/화면은 로컬 `test-results/`에 기록하며 Git에는 비밀/세션 토큰을 포함하지 않은 결과만 별도로 보관한다.

## 배포 판단과 남은 실행

- 구현과 로컬 자동검사는 실제 마이크 인수와 별개다. 실제 iPhone의 권한 허용/거절·말소리 인식·중지 시 실제 마이크 종료·오인식 정정 후 저장·소리 품질은 미확인이다. 오류가 전혀 없다고 선언하지 않는다.
- 현재 환경에 iPhone 원격 제어·실제 오디오 장치·Render 관리 인증이 없다. 새 음성 유료 서비스/외부 계정/키를 도입하지 않았다.
- [실제 마이크 인수 절차](MICROPHONE_ACCEPTANCE.md)에 별도 무료 시험 서버와9개 실기기 검사, 결과 회신 형식, 운영 배포 조건을 정리했다. 실제 시험 주소는 아직 발급되지 않았다.
- 공개 GET에서 운영 서비스는0.8.0/schema7이다. 이 관찰은 저장소 병합 전 공개 버전이다. 최신 지시에 따라 PR #2의 main 병합·동일 SHA CI를 진행하며 최종 배포 SHA는 완료 보고와 GitHub main에서 대조한다. 이번 준비 자체가 Render 운영 배포나 실제 마이크 인수 완료는 아니다.
