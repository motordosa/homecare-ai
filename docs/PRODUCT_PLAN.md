# 제품 기획 v0.8.0

## 목적과 경계

고령 환자의 일상 기록 부담을 줄이고 의료진이 영양·복약·활동·수면 변화와 자료의 신뢰도를 함께 확인하도록 한다. 환자는 모바일 웹, 의료진은 데스크톱 웹을 유지한다. 합성 체험(demo)과 카카오 인증(kakao) 모드를 구분하며 실제 연구 운영은 인증·동의·기관 승인·보존 정책을 별도 완성한 뒤 시작한다.

## 단계별 실행

1. **기준 수립:** 현황/공식 근거 조사, 계약과 변경 프로세스 저장. 완료 뒤 코드 변경 시작.
2. **기본 동작 정상화:** 메뉴·부분 저장 결함, 의료진 처방과 회차별 복약. 기존 일일 자기보고는 호환성 유지.
3. **사진 분석:** 실제 외부 제공자 어댑터와 초안 확인 UI, 키 없는 상태·재시도·오류·환자 분리·중복 적용 검증. 실제 서비스 키 없이 분석 정확도 검증 완료라고 주장하지 않음.
4. **건강 연동:** 2026-10-17의 최신 요청으로 **iPhone·Apple Health 우선**으로 변경한다. IOS_CONNECTOR.md가 현재 우선 계약이며 기존 Android는 유지한다. 실제 권한·기기·백그라운드 검증 후 자동 수집 완료로 전환한다.
5. **연구 전환:** 로그인/권한/동의/암호화·감사·보존/삭제·운영 DB, 실제 한국 식사 검증 자료, 약·기기별 임상/사용성 검증.

## 임상/사용성 판단

- 사진에서 실제 섭취량, 숨은 재료·기름·정확한 중량을 알 수 없다. AI가 초안을 채워 입력을 줄이고 환자가 먹은 양을 확인한다. 확인은 자기보고 확인이며 영양량의 임상 검증과 다르다.
- 약 사진의 포장 글자는 후보를 줄 뿐이다. 비슷한 알약 외형만으로 약을 확정하지 않는다. 의료진 목록을 복약 판단 기준으로 한다.
- 미복용 사유로 불편·망각·거부 등을 기록할 수 있다. 환자의 미복용 보고를 의료진의 중단 지시로 바꾸지 않는다.
- 걸음 수·수면은 폰/워치 저장소에서 플랫폼이 집계한 값을 받아 이중 합산을 피한다. 자동 수집 주기는 OS 정책에 따라 달라지며 실시간/상시 보장을 하지 않는다.
- 현재 무료 데모 호스팅의 영양 AI 비용과 별도 모바일 앱 배포 비용은 서버 무료 요금제와 다르다.

## 2026-10-21 검토 우선순위 — 제안 단계

사용자 요청에 따라 카카오 실제 활성화·건강 기기 실연동은 우선 보류하고, 국내 약 사진으로 복약 입력 부담을 줄이는 개발안을 검토한다. 기존 구현을 제거하지 않는다. MEDICATION_PHOTO_KR_PROPOSAL.md의 A(포장 OCR·개인 목록·확인 후 회차 기록)→B(국내 품목 대조)→C(낱알 후보)의 순서를 제안한다. 아직 새 기능의 구현·정확도·공식 API 명세/실호출 검증 완료가 아니며 채택 후 화면/계약을 먼저 확정한다.

### MED-PHOTO-01 승인 범위 (2026-10-21)

사용자 승인으로 빠른 A단계 개발을 진행한다. 약봉투/포장 글자 읽기와 기존 계획 대조, 환자의 회차별 자기보고·사진 첨부, 의료진 조회. 상세 제작 기준은 MEDICATION_PHOTO_DEMO_SPEC.md. 국내 품목 API와 낱알 식별은 후속이며 새 처방/복용 자동 확정 없음.

## v0.7.0 승인된 개선 실행 (2026-10-23)

사용자 지시: 전략·계획을 만들고 순서대로 수정한 후 검증 결과 보고. USABILITY_IMPLEMENTATION_PLAN의 6단계/B·P·W·S·L 요구를 현재 구현 범위로 채택한다. 카카오/건강 실연동 보류와 전문 통계/AI 문헌 요약의 별도 관문은 유지한다. 오늘 행동·쉬운 기록·입력 보존, 역할/업무·원자료/정정·지표/기술통계·근거검토가 대상이며 실제 연구 정책 승인을 대신하지 않는다.

## v0.8.0 환자 화면·음성 개선 (2026-10-24, 구현 전)

현재 새 변경의 요구·화면/상태·데이터·지원 범위·변수·검증 기준은 [PATIENT_VOICE_SPEC.md](PATIENT_VOICE_SPEC.md)를 따른다. 기존 v0.7.0 공통 규약을 계승하며 환자 본문20/도움18/누름56 목표, 행동/정보 구분과 인라인 음성 안내·음성 입력·할 일 알림을 추가한다. 기존 의료진/네이티브와 환자 기록 API는 유지하고 공지 영수증 테이블은 schema7로 추가한다. 음성 인식 결과는 확인 후 기존 입력칸에만 반영한다. 녹음·원고 자동 저장·백그라운드 전달을 구현 완료로 표시하지 않는다.
