# 제품 기획 v0.3

## 목적과 경계

고령 환자의 일상 기록 부담을 줄이고 의료진이 영양·복약·활동·수면 변화와 자료의 신뢰도를 함께 확인하도록 한다. 환자는 모바일 웹, 의료진은 데스크톱 웹을 유지한다. 현재는 로그인 없는 합성 데이터 데모이며 실제 연구 운영은 인증·동의·기관 승인·보존 정책을 별도 완성한 뒤 시작한다.

## 요구사항과 인수조건

| ID | 요구 | 인수조건 |
|---|---|---|
| GOV-01 | 기획/계약을 코드보다 먼저 갱신 | 저장소 AGENTS와 문서 색인, 변경 이력, 변수 목록이 연결됨 |
| NAV-01 | 메뉴 목적에 맞는 입력 | 걸음 수·수면·복약별 제목/필드/저장 payload가 다름 |
| NAV-02 | 미보고 값 보존 | 복약만 저장해도 식욕·기분·활동·수면이 자동 생성되지 않음 |
| NAV-03 | 조회와 작성 구별 | 영양 카드는 근거 식사를 조회, 식사 목록으로 직접 이동, 현재 화면/환자 URL 복원 |
| MED-01 | 의료진의 확정 복약계획 | 약명·함량·1회량·시간·기간·주의문을 등록하고 환자별 조회 |
| MED-02 | 약·날짜·회차별 자기보고 | 복용/미복용/기억 안남, 사유·메모, 수정 이력이 보존됨 |
| MED-03 | 과거 기록과 미응답 보존 | 일정 변경/종료가 과거 복용 기록을 지우지 않음. 미응답을 자동 미복용으로 바꾸지 않음 |
| IMG-01 | 식사 사진 자동 분석 보조 | 사진→서버 AI→음식/영양 추정 초안→환자 섭취비율 확인→기록 |
| IMG-02 | 약 사진 작성 보조 | 포장/약봉투의 읽을 수 있는 이름·함량 후보를 의료진이 확인. 처방/복용 확정 금지 |
| IMG-03 | 분석 출처·실패 처리 | 제공자/모델/시간/추정/확인 여부 보존. 키 미설정·실패 시 명확한 안내와 수동 입력 |
| SYNC-01 | 걸음 수·수면 자동 연동 기반 | 플랫폼 권한을 가진 네이티브 연결부와 서버 계약 분리. 웹 직접수집으로 표시하지 않음 |
| SYNC-02 | 중복·수정·출처 관리 | 재전송은 중복 생성하지 않음. 폰/워치 합계 중복 가산 금지. 수동값과 기기값을 구별 |
| QA-01 | 실제 동작의 검증 | 임시 DB/API/모바일/데스크톱 테스트. 실제 AI/기기/공개 배포 미검증은 별도 명시 |

## 단계별 실행

1. **기준 수립:** 현황/공식 근거 조사, 계약과 변경 프로세스 저장. 완료 뒤 코드 변경 시작.
2. **기본 동작 정상화:** 메뉴·부분 저장 결함, 의료진 처방과 회차별 복약. 기존 일일 자기보고는 호환성 유지.
3. **사진 분석:** 실제 외부 제공자 어댑터와 초안 확인 UI, 키 없는 상태·재시도·오류·환자 분리·중복 적용 검증. 실제 서비스 키 없이 분석 정확도 검증 완료라고 주장하지 않음.
4. **건강 연동:** 서버 수신·출처·중복 방지와 연결 상태 UI를 먼저 준비. 사용자 선택에 따라 Android·갤럭시 워치를 우선하며 상세 계약은 ANDROID_CONNECTOR.md에 따른다. 네이티브 연결부의 실제 권한·기기·백그라운드 검증 후 자동 수집 완료로 전환한다.
5. **연구 전환:** 로그인/권한/동의/암호화·감사·보존/삭제·운영 DB, 실제 한국 식사 검증 자료, 약·기기별 임상/사용성 검증.

## 임상/사용성 판단

- 사진에서 실제 섭취량, 숨은 재료·기름·정확한 중량을 알 수 없다. AI가 초안을 채워 입력을 줄이고 환자가 먹은 양을 확인한다. 확인은 자기보고 확인이며 영양량의 임상 검증과 다르다.
- 약 사진의 포장 글자는 후보를 줄 뿐이다. 비슷한 알약 외형만으로 약을 확정하지 않는다. 의료진 목록을 복약 판단 기준으로 한다.
- 미복용 사유로 불편·망각·거부 등을 기록할 수 있다. 환자의 미복용 보고를 의료진의 중단 지시로 바꾸지 않는다.
- 걸음 수·수면은 폰/워치 저장소에서 플랫폼이 집계한 값을 받아 이중 합산을 피한다. 자동 수집 주기는 OS 정책에 따라 달라지며 실시간/상시 보장을 하지 않는다.
- 현재 무료 데모 호스팅의 영양 AI 비용과 별도 모바일 앱 배포 비용은 서버 무료 요금제와 다르다.
