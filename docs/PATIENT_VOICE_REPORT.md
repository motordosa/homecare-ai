# HomeCare AI v0.8.0 환자 화면·음성·공지 수정 보고서

2026-10-24 KST. 기준 코드9c6351a/v0.7.0/schema6에서 수정했다. 구현 버전은 v0.8.0/schema7이다. 김박사님의 두 개발 지시를 함께 반영했고, 실행계획·제작 규약을 먼저 [PATIENT_VOICE_SPEC](PATIENT_VOICE_SPEC.md)에 기록했다.

환자 화면의 행동/정보 구분, 한국어 안내·확인형 음성 입력·화면 열림 알림을 구현했다. 공지 문제는 기본 임시 저장과 게시 혼동, 같은 브라우저의 데모 역할 세션 충돌, 저장 응답 손실 후 중복 생성 경로를 재현·보완했다. 공개 서버에서 확인한0.7.0과 최신 로컬 코드의 결과를 아래에서 구분한다. 이번 작업은 공개 배포는 실행하지 않았다.

## 5. 공개 서비스와 저장소 상태

공개 주소: https://homecare-ai-demo.onrender.com. 2026-10-24 13:13 KST 공개 API 점검 시점은 **v0.7.0/schema6**이었다. HTTPS curl은 정상 인증서 검증으로 접근했다. 공개 Chromium은 `ERR_CERT_AUTHORITY_INVALID`로 화면을 열지 못해 공개 화면 클릭을 수행했다고 표시하지 않는다.

공개 API에서는 합성 공지1건만 만들어 draft→공유 쿠키 충돌403→분리 세션 publish200→환자 active API의 두 차례 수신을 확인했다. 종료 시 **해당 합성 공지를 archived로 보관**했다. 이 검사는 HTTP 검증이며 실제 공개 UI 새로고침 클릭의 증거는 아니다. 로컬에서는 같은 흐름을 실제 클릭·새로고침으로 검증했다. 공개 배포는 수행하지 않았다.

새 코드는 검토 브랜치 `codex/patient-voice-notices`에서 관리하고 최종 커밋/PR 링크는 완료 답변으로 제공한다. 현재 main의 공개 배포와 이 브랜치를 혼동하지 않는다. 배포 전까지 기존0.7.0에서 두 역할을 시험할 때는 환자와 의료진을 별도 브라우저/시크릿 컨텍스트로 분리하고, 의료진 화면을 다시 연 뒤 **게시** 상태를 선택하면 확인할 수 있다.

## 6. 남은 결정·제약

- 새 유료 서비스·API 키 없이 구현했다. 브라우저/OS의 한국어 목소리·Web Speech 지원·마이크 허용·네트워크에 따라 인식/발화가 실패할 수 있다. 실제 iPhone Safari/Android Chrome에서 테스트 문장·허용/거절·음량·멈춤·오인식 수정·저장을 확인해야 한다.
- 현재는 모바일 웹의 보조 기능이다. 기존 iOS/Android 연결 앱을 음성 앱으로 변경하지 않았고 로컬에서 네이티브 전체 빌드/실기기 검증을 수행하지 않았다. PR의 GitHub Android/iOS 빌드 결과는 별도 CI 결과로 확인한다.
- 화면 종료/잠금 뒤 예약·푸시가 필요하면 PWA/네이티브 알림·수신 동의·운영 정책을 별도 결정한다. 현재 알림은 기록 권유이며 약 복용 시각 보장 수단이 아니다.
- 실제 고령자 과제 평가, 기관 필수 기록/대응 시간, 대상별 비공개 공지·실제 연구 운영은 후속이다. [사용자 실행 보고서](USER_ACTION_REPORT.md)에 실제 기기·역할 확인 절차를 정리했다.
