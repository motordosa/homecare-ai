# 카카오 로그인·공지·개별 메시지 활성화 안내 v0.6

2026-10-20 KST. 구현과 임시 DB 검증을 완료한 뒤 계정 소유자가 실행할 외부 설정이다. 실제 카카오 앱 키·Render 관리 인증은 현재 개발 환경에 없으므로 제공자 로그인 성공이나 공개 배포 완료를 주장하지 않는다. 개발 클라우드 설정은 Render에 자동 복사되지 않는다.

## 1. 카카오 앱 준비

1. [Kakao Developers](https://developers.kakao.com/)에 본인 계정으로 로그인하고 HomeCare용 애플리케이션을 선택하거나 만든다. 관리 화면의 명칭이 변경되면 카카오 로그인/플랫폼/보안 항목에서 같은 설정을 찾는다.
2. 웹 서비스 도메인에 `https://homecare-ai-demo.onrender.com`을 등록한다. 카카오 로그인을 활성화한다.
3. Redirect URI에 **`https://homecare-ai-demo.onrender.com/auth/kakao/callback`**을 정확히 등록한다. 다른 서비스 주소라면 그 HTTPS origin으로 통일한다. 끝에 `/`를 더하지 않는다.
4. 앱 키에서 **REST API 키**를 확인한다. JavaScript 키나 Admin 키를 사용하지 않는다. 카카오 로그인 보안에서 **Client Secret을 생성하고 활성화**한다. 이 구현은 활성화된 Client Secret을 요구한다.
5. 닉네임·이메일·사진·친구목록 동의 항목은 이 기능에 필요하지 않다. 서버는 카카오 앱 사용자 ID만 확인한다. 개발/테스트 앱이면 실제 로그인할 계정이 허용된 테스트 사용자/팀 멤버인지 확인한다. 앱의 공개 사용 가능 상태는 카카오 콘솔에서 확인한다.
6. 키와 비밀번호는 채팅·문서·Git에 보내지 않는다. Render의 비공개 Environment 입력란에만 넣는다.

참고 공식 문서: [REST API](https://developers.kakao.com/docs/latest/ko/kakaologin/rest-api), [카카오 로그인 설정](https://developers.kakao.com/docs/latest/ko/kakaologin/prerequisite). 이번 환경의 공식 문서 접속은 프록시 거부로 내용을 새로 검증하지 못했다. 실제 앱의 허용 계정/동의창/정책은 소유자의 콘솔에서 최종 확인한다.

## 2. Render 설정과 배포

[Render Dashboard](https://dashboard.render.com/) → `homecare-ai-demo` → **Environment**에서 아래를 설정한다. 기존 GPT 키·모델·DATA_DIR는 보존한다.

| 이름 | 입력할 값 |
|---|---|
| AUTH_MODE | `kakao` (실제 인증/본인 기록만 접근) |
| APP_ORIGIN | `https://homecare-ai-demo.onrender.com` |
| KAKAO_CLIENT_ID | 카카오 앱의 REST API 키 |
| KAKAO_CLIENT_SECRET | 활성화한 Client Secret |
| CLINICIAN_KAKAO_IDS | 처음에는 비워 두고 다음 절차에서 본인 사용자 ID 등록 |
| NODE_ENV | `production` |

저장 후 배포한다. 자동 배포가 꺼진 서비스는 **Manual Deploy → Deploy latest commit**을 누른다. Branch가 `main` 또는 `codex/free-demo-deploy`인지 확인한다. GitHub 최신 커밋과 Render 배포 커밋이 같은지 대조한다. 빌드/기동 후 `/api/health`의 `schemaVersion:4`, `/api/auth/session`의 `mode:kakao`, `kakaoAvailable:true`를 확인한다. 이는 설정 형식 검사이며 실제 카카오 로그인 성공의 증거가 아니다.

기존 서비스를 수동으로 만든 경우 `render.yaml` 변경이 Environment에 자동 적용되지 않을 수 있다. 키 준비 전 합성자료 체험만 계속하려면 **AUTH_MODE=demo**를 명시한다. 이 모드는 보안 경계가 없는 공동 체험이므로 실제 개인정보를 넣지 않는다. 키가 없는 `kakao` 모드는 보호 API를 잠그며 자동으로 demo로 바뀌지 않는다.

현재 무료 Render의 `/tmp/homecare-data`는 재배포/재시작 때 초기화될 수 있다. 공지·메시지·계정 연결도 이 SQLite에 들어간다. CSV는 메시지·인증·공지 백업이 아니며, 중요한 자료의 영구 보관용 배포가 아니다. 무료 체험에 실제 환자/연구 자료를 넣지 않는다.

## 3. 첫 의료진 등록

1. `https://homecare-ai-demo.onrender.com/login?next=/clinician`을 연다. **카카오 로그인**을 누르고 동의하여 돌아온다.
2. 처음에는 권한이 없는 **계정과 환자 연결** 화면이 나온다. **내 카카오 앱 사용자 ID 확인**을 펼쳐 본인의 숫자 ID를 확인한다. 카카오 이메일/전화번호와 다른 앱 전용 ID다.
3. Render Environment의 `CLINICIAN_KAKAO_IDS`에 그 숫자 ID를 입력하고 저장/재배포한다. 의료진 여러 명이면 쉼표로 나눈다. 예시 숫자를 그대로 등록하지 않는다.
4. 같은 계정으로 다시 로그인하거나 계정 화면을 새로 열어 **의료진 화면 열기**를 누른다. 의료진 메뉴는 대시보드/환자 관리/복약 계획/건강 기록/공지 관리/환자 메시지/데모 설정의 7개다.
5. 이 목록에서 ID를 제거하면 해당 계정의 기존 세션에서도 의료진 권한이 사라진다. 관리자 외 사용자에게 Render 관리 권한을 주지 않는다.

## 4. 환자 연결과 사용

1. 의료진 화면 → 환자 관리 → 해당 환자 선택 → **환자 연결코드**. 환자 메시지 화면에서도 같은 버튼을 쓸 수 있다.
2. 본인 확인 후 해당 환자에게만 코드를 전달한다. 24시간/1회 사용이다. 새로 발급하면 이전 미사용 코드는 무효다. 닫으면 화면에서 코드가 제거된다.
3. 환자는 자신의 휴대전화에서 `/login?next=/patient`로 카카오 로그인한다. 연결 대기 화면에 의료진의 코드를 입력한다. 한 카카오 계정은 한 환자 기록에만 연결된다.
4. 환자는 본인 기록과 메시지만 확인한다. 환자 화면 상단에는 게시된 의료진 공지, 하단에는 **메시지**가 나타난다. 모든 서브 화면 우상단 X는 같은 환자 홈으로 돌아간다.
5. 의료진 공지 관리에서 제목/본문/중요 여부를 정하고 **게시**로 저장하면 상단에 나타난다. **임시 저장**은 환자에게 보이지 않고 **보관**은 게시를 내린다. 수정된 공지는 다시 미확인으로 표시된다.
6. 의료진 → 환자 메시지 → 환자 이름을 선택하고 전송한다. 환자는 자신의 메시지 화면에서 답장한다. 읽음은 상대 역할이 대화 화면을 확인한 경우에만 표시한다. 의료진의 모든 사용자에게 동시에 읽음을 표시하는 것이 아니라 본인 대화 확인 순번을 사용한다.
7. 이 기능은 **사이트 내 수신함**이다. 카카오톡·SMS·푸시를 보내지 않는다. 자동 조회는 보이는 탭에서 약15초마다이므로 즉시 알림이나 응급 연락 수단이 아니다.
8. 같은 브라우저의 여러 탭은 로그인 계정을 공유한다. 환자/의료진을 동시에 시험할 때는 다른 브라우저 또는 별도의 비공개 창 프로필을 사용한다.

## 5. 배포 후 확인과 문제 해결

합성 환자만 있는 테스트 배포에서 두 계정/브라우저로 확인한다. 실제 공개 자료를 초기화하지 않는다.

| 확인 | 기대 결과 |
|---|---|
| 비로그인 상태의 보호 API 직접 접근 | 401, 자료 미노출 |
| 환자의 의료진 화면 접근 | 계정 안내, 의료진 API는 403 |
| 다른 patientId·사진 URL 접근 | 403 또는 자료 없음, 다른 환자 자료 미노출 |
| 공지 초안→게시→수정→보관 | 환자 미노출→상단 노출→새 확인 필요→미노출 |
| 환자 A 메시지 | A에게만 노출, B에게 없음; 답장과 읽음 반영 |
| 글 작성 후 새로고침/화면 전환/뒤로 | 자동 갱신은 초안 유지, 이탈은 확인 |
| 의료진 건강 기록→설정→브라우저 뒤로 | 건강 기록 복귀 |
| 로그아웃 후 API/화면 재접근 | 세션 폐기, 로그인 필요 |
| 기존 GPT·iPhone 메뉴 | 기존 출처·설정·연결 절차 유지 |

- 카카오 버튼 없음: `/api/auth/session`의 mode/설정 준비 상태와 환경 변수 이름을 확인한다. 키를 보여주는 화면은 만들지 않았다.
- 카카오 오류/로그인 실패: REST 키·활성 Client Secret·정확한 redirect URI·허용 테스트 계정을 확인한다. 개인 키나 원문 OAuth URL을 공유하지 않는다. 앱은 원문 토큰/제공자 오류를 화면에 출력하지 않는다.
- 의료진 권한 없음: 같은 앱에서 확인한 본인 숫자 ID를 서버 allowlist에 등록하고 재배포한다. 화면에서 역할을 선택해 승격하는 기능은 없다.
- 초대 실패: 만료/사용/재발급 여부와 이미 연결된 계정인지 확인한다. 다른 환자에 자동 재할당하지 않는다.
- 공지 수정 충돌: 초안을 복사해 보관한 뒤 목록 새로고침→공지 재선택으로 최신 버전을 확인하고 수정한다. 충돌 때 작성 중 값은 유지한다.
- 재배포 후 환자 연결 소실: 무료 임시 DB가 교체됐는지 확인한다. 같은 환자 ID가 다시 생성돼도 실제 계정 연결을 자동 복구하지 않는다.

`npm run demo:check -- https://homecare-ai-demo.onrender.com`은 GET만 수행하는 익명 점검이다. 화면 소스 일치·공개 health/인증 상태·로그인 화면을 검사하며 실제 카카오 인증 후 인수나 제공자 성공을 대체하지 않는다. 임시 DB의 전체 검사 명령은 README에 있다.

## 6. 개발 클라우드 설정 초안

개발 환경 초안에는 Kakao 설정 변수·Client Secret 요구와 `developers.kakao.com`, `kauth.kakao.com`, `kapi.kakao.com` 목적지를 추가해 두었다. 저장된 초안은 실행 환경에 자동 적용되지 않는다. 환경 설정에서 변경을 검토·저장하고 환경을 게시해야 적용된다. 키는 보안 설정에 직접 입력하며 초안 저장 자체가 키 발급이나 바인딩 성공을 뜻하지 않는다. 이 절차와 Render Environment 저장/배포는 서로 별개다.
