# HomeCare AI v0.7.0 구현·검증 보고서

기준일: 2026-10-23. 저장소: motordosa/homecare-ai. 구현 기준: v0.6.1/schema5 → v0.7.0/schema6. 사용자의 수정 지시에 따라 실행계획·계약을 먼저 기록하고, 화면·서버·자료 구조를 구현한 뒤 임시 합성 DB에서 검증했다. 이 보고서는 로컬 구현 상태를 설명한다. 이번 작업에서 Git push나 Render 배포를 실행하지 않았다.

## 1. 적용 전략과 추적 기준

목표는 고령 환자의 입력 부담과 실수를 줄이고, 의료진·지원 인력·연구자의 업무와 권한을 명확히 나누는 것이다. 기존 보고서의 버전 순서는 단계별 의존성을 나타낸다. 이번에는 검증 가능한 업무·연구·문헌의 기본 기능까지 v0.7.0 데모에 통합했으며, 원계획의 모든 연구 운영 관문을 완료했다는 뜻은 아니다.

1. **기준 확정:** [실행계획](USABILITY_IMPLEMENTATION_PLAN.md), 제품 기획·화면·API·변수 의미를 먼저 정리했다.
2. **기본 결함 수정:** 작은 글자·대비·공지 적체·미저장 이탈·중복 재시도·보고일 계산·CSV 범위를 수정했다.
3. **환자 작업 개선:** 명시적 식사 선택, 시간대별 복약, 사진 처리, 단위 안내, 도움 요청, 지속 완료 표시를 적용했다.
4. **직무별 업무 추가:** 서버 역할/환자 배정, 업무 목록, 사진 검토, 원기록 정정, 참여·위임 계획을 연결했다.
5. **연구·문헌 기본 기능:** 기술통계, 동결 가명자료 반출, 검색·보관·사람 검토를 구현했다.
6. **통합 검증:** 기존 회귀, 새 API·브라우저 검사, 독립 코드 검토, 생성 문서 대조를 수행했다.

원보고서의 **36개 작업과 38개 발견사항을 전부 추적**한다. [작업별 상태 CSV](research/usability-implementation-2026-10-23/execution-status.csv)와 [발견사항 대응 CSV](research/usability-implementation-2026-10-23/finding-trace.csv)에 구현·부분 완료·외부 대기와 남은 조건을 기록했다. 아래 기능 구현은 실제 고령자 과제 성공률 또는 임상 유효성의 검증을 뜻하지 않는다.

## 3. 의료진·지원 인력 화면의 변경

기존 데스크톱 셸에 **업무 목록·연구 분석·문헌 검토**를 추가했다. 전체10개 메뉴 중 서버 권한에 맞는 메뉴만 표시하며, URL/API 직접 호출도 서버가 검사한다. 실제 모드의 지원 인력에게 임상 승인·자유 임상 메시지·관리자료 반출 권한을 부여하지 않는다. 관리자는 역할만으로 임상 기록 권한을 얻지 않는다. 실제 모드 전체 초기화는 거부한다.

- **공통 작성 보호:** 복약계획 등 대화상자의 X/Escape/메뉴/환자 변경/뒤로/로그아웃에 동일한 미저장·저장 중 보호를 적용했다. 갱신이 열린 상세·포커스·스크롤·작성 중 내용을 덮지 않도록 했다.
- **업무 목록:** 환자별 연락·자료 확인·사진/임상 검토 업무의 담당자, 기한, 상태, 변경 이력을 관리한다. 지원 인력이 임상 검토를 단독 종결할 수 없다. 완료 임상 업무는 지원 인력에게 읽기 전용이다.
- **사진 검토:**20건 단위 페이지로 과거 보고를 읽고 미검토/추가정보/검토완료 상태를 관리한다. 저장 당시 사진과 회차 snapshot은 보존한다. 환자 응답에는 공개 상태만 주며 직원 내부 메모는 제외한다.
- **원기록 정정:** 기기 보완값과 분리된 직접 입력 원본을 읽고, 정정안·사유·원본 수정번호를 제출한다. 임상 권한의 승인/반려와 감사 이력을 남기며 원본이 바뀌면409로 재검토한다. 현재 정정 UI는 일일 기록의 걸음·수면·체중 대상이며 서버는 추가 상태·메모 필드도 지원한다.
- **참여·위임 계획:** 참여/휴지/철회/완료, 기간·동의 버전·필수 항목을 저장한다. 위임 기간·범위·철회 기반도 구현했지만 **실제 보호자 접근은 비활성**이다. 참여 상태에 따른 자동 수집/연구 제외 정책은 기관 승인 후 연결해야 한다.
- **기간·지표:** 선택 기간과 보고 분모를 표시하고 복약만 있는 날도 포함한다. 과거 기간의 보고 카드 기준은 실제 오늘이 아니라 선택 마지막 날이다. 위험 표시의 고정7일 규칙과 선택 기간을 구분한다. 그래프에는 수치 표를 제공한다.
- **관리 CSV:** 환자·기간·열·행수 미리보기 후 반출하며 조건이 바뀌면 재확인한다. 식별 가능한 관리 자료와 가명 연구 자료를 구별한다.

## 4. 연구 분석·문헌 검토

**연구 분석은 기술통계 범위다.** 대상·기간·출처를 선택하고 환자 수, 관측 수, 유효값, 결측, 평균, 표본 표준편차, 중앙값·사분위수와 환자별 평균 분포를 구분한다. 반복 관측을 독립 환자 수로 표시하지 않는다. 결측 자동 대치·유의확률·전문 통계모형은 제공하지 않는다.

미리보기 이후 자료가 바뀌면 저장을 차단한다. 확인한 자료는 가명 ID·분석 조건·입력 해시·버전·생성 시각을 포함해 불변 스냅샷으로 보관한다. CSV와 manifest의 해시를 실제 브라우저 다운로드 바이트로 대조한다. 기본 연구 반출에는 이름·자유서술·사진이 없고, 재조회/반출 시 현재 접근 범위를 다시 검사한다. 참여/철회 정책을 자동 반영한 승인 연구 데이터셋은 아직 아니다.

문헌은 Europe PMC 고정 제공자 검색, 결과0건/장애/429/시간초과 구분, 검색 조건·결과 보관, 북마크, 포함/제외/사람 검토를 지원한다. 검토에는 근거 구절·위치·메모를 남긴다. 실제 검색 결과의 식별자만 보관하며 초록·외부 전문 검토 범위를 구별한다. 제공자가 확인하지 않은 철회 상태는 불명으로 둔다. **실제 외부 연결은 이번 환경에서 검증하지 않았으며 자동화는 모의 제공자를 사용했다.** AI 문헌 요약은 미구현이다.

## 5. 데이터 보존과 기획 문서 관리

기존 DB 파일을 지우지 않는다. 식사의 영양/섭취량 null 지원은 알려진 기존 스키마만 트랜잭션으로 이행하며 행수·내용·FK 보존을 확인한다. 예상하지 못한 컬럼·의존 관계는 임의 삭제하지 않고 이행을 중단한다. 업무·감사·참여·위임·연구·문헌 테이블은 추가한다. 일일 기록의 수정번호와 저장 영수증으로 충돌·응답 손실을 구분한다.

문서 체계는 `PRODUCT_PLAN → SCREEN_SPEC → CONTRACTS/전용 명세 → DATA_DICTIONARY → 코드 → 검증/CHANGELOG` 순서다. 새 기능의 파일별 선언·함수 인자·위치는 [변수 목록](generated/VARIABLES.md), 실제 DB 컬럼·제약은 [스키마 목록](generated/SCHEMA.md)으로 재생성한다. 자동 목록은 변수 의미와 화면 제작 규약을 대체하지 않는다. CI에 새 사용성 브라우저 검사를 추가했다.

## 7. 남은 관문과 확인 방법

현재 결과는 **개선된 데모 구현**이다. 실제 고령자·지원 인력·의료진의 과제 평가, 확대/보조기술·실기기 종합평가, 기관 연구정책 승인, 운영 부하시험·영구DB/백업복원, 실제 문헌 연결과 기존 AI 정확도 검증은 별도다. 카카오·건강기기 실제 활성화는 기존 사용자 요청에 따라 보류했다. 세부 요청은 [사용자 실행 보고서](USER_ACTION_REPORT.md)에 정리했다.

로컬 확인은 Node24에서 `npm ci` 후 `npm start`를 실행하고 기본 포트3000의 `/patient`와 `/clinician`을 연다. 설치된 개발 환경에서는 `npm start`만으로 실행할 수 있다. 실사용 자료를 입력하지 말고 가상 환자로 확인한다. 환자 식사→양 모름/안 먹음, 복약→날짜/회차 저장, 의료진 업무→정정 검토, 연구→조회/스냅샷/CSV, 문헌→검색/보관 순서가 권장 시연 경로다. 문헌 실제 검색은 서버의 외부 연결이 가능해야 한다.

이 작업은 저장소 수정·검증까지 수행했다. 공개 주소 `https://homecare-ai-demo.onrender.com`의 버전이 이번 코드로 바뀌었다고 판단하지 않는다. 배포 시 연결 Git 브랜치 반영, schema6 시작 로그·health 버전, 기존 자료 보존과 주요 화면을 별도로 확인해야 한다.
