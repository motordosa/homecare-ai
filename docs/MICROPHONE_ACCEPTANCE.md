# 실제 iPhone Safari 마이크 인수

2026-10-25 KST. v0.8.1의 **미완료 실기기 검증 항목**이다. SpeechRecognition 모의 콜백·문장 파서 검사·실제 Chromium 클릭은 실제 iPhone 마이크 검사와 다르다. 현재 개발 환경에는 iPhone/오디오 장치 원격 제어와 Render 관리 인증이 없다. 미검증 보고 후 사용자가 최종 커밋을 배포할 수 있도록 준비하라고 지시했다. 이에 따라 main 병합·CI·배포 인계는 진행하되 실제 마이크 검증 완료로 표시하지 않는다.

## 검사할 버전과 테스트 서버

운영 사이트는 https://homecare-ai-demo.onrender.com 의0.8.0/schema7이다. 그 사이트에서 검사해도0.8.1 수정 검증이 되지 않는다. 수정 코드는 `d3dd1dd`에 있으며 PR #2를 main에 병합한 뒤 실제 시험 SHA를 기록한다. 시험 서버의 `/api/health`가0.8.1/schema8인지 확인한다.

아이폰에서 수정본에 접속할 HTTPS 환경이 필요하다. 별도 시험 서버를 쓰려면 다음 절차를 사용하고, 기존 데모 서비스 배포는 DEPLOY_RENDER.md의 main 기준 절차를 따른다. Render 관리 접근이 없는 현재 환경에서는 소유자가 아래 절차로 준비할 수 있다. 기존 운영 서비스의 Branch를 바꾸지 않는다.

1. [Render 대시보드](https://dashboard.render.com) → **New → Web Service**. 기존 GitHub 저장소 `motordosa/homecare-ai` 선택.
2. 이름은 `homecare-ai-voice-test` 등 별도 이름, Branch는 **codex/patient-reliability-fixes**, Runtime은 **Docker**, Instance Type은 **Free**, Health Check Path는 `/api/health`, 자동 배포는 **Off**. 유료 선택만 가능하면 생성하지 않고 다른 무료 시험 환경을 정한다.
3. 환경 변수: `NODE_ENV=production`, `AUTH_MODE=demo`, `DATA_DIR=/tmp/homecare-data`, `VISION_ENABLED=false`. 마이크/화면 검사에 GPT·카카오 키는 필요 없다. `APP_ORIGIN`은 생성 화면에 나온 새 시험 HTTPS 주소로 지정한다. 기존 운영 주소를 넣지 않는다.
4. 생성 후 Live·시험 주소·배포 SHA·health 버전/스키마 확인. 운영과 다른 임시 합성 DB를 사용한다. 무료 서버의 절전/재시작으로 시험 기록이 사라질 수 있다.
5. 새 주소를 아이폰 Safari에서 열고 가상 환자를 선택해 아래 검사를 수행한다.

이 절차는 아직 실행된 시험 서버가 아니다. 현재 수정 코드의 공개 시험 URL은 발급되지 않았다. Render 화면 표기가 달라지면 브랜치·무료 요금·환경 변수를 확인한다.

## 실제 듣고 말하는 검사

기종/iOS/Safari 또는 홈 화면 실행/URL/SHA/검사 시각을 기록한다. 사용자 기기 우선이며 작은 화면 기기를 포함한2종 iPhone 검사를 목표로 한다. 조용한 실내와 일상 소음 환경을 구별하고 합성 문장만 사용한다.

| 번호 | 직접 실행 | 통과 기준 |
|---|---|---|
| M01 | 홈 안내 듣기·중지·다시 듣기. 이용 안내→목소리·3속도 미리듣기 | 실제 한국어 소리, 잘림/겹침 없음. 중지하면 실제 소리도 종료. 이해하기 쉬운 설정 기록 |
| M02 | 걸음 수→조회 완료→말로 입력→처리 안내 체크→마이크 켜기→최초 허용→`삼천 오백 걸음` 발화 | 실제 권한/마이크 표시 및 음성으로 생성된 글 확인.3500 검토. 타이핑을 인식 성공으로 기록하지 않음 |
| M03 | 인식 글을 `삼천 육백 걸음`으로 고침→내용 확인→날짜/내용 체크→적용→저장 | 확인 전 원래 입력값/서버 불변. 저장 후3600/날짜가 내 기록·의료진 조회와 일치, 새로고침 보존 |
| M04 | 다시 말하기에서 무음·중지·인터넷 끊김·복구 | 이전 편집 문장 보존. 중지2초·전체25초 내 UI 복구. 실제 마이크 표시가 사라지는지 별도 확인 |
| M05 | 마이크 권한 거절→직접 입력. Safari 사이트 설정에서 허용 후 재시도 | 거절 안내와 수동 저장 가능. 다시 허용한 뒤 실제 말소리 인식 |
| M06 | 시작/중지20회, 안내 중 마이크, 인식 중 잠금/앱 전환/뒤로 이동 후 복귀 | 안내·마이크 겹침/화면 잠김/다른 폼·날짜에 이전 결과 반영 없음 |
| M07 | `일곱 시간 반 잤어요`, `밥과 반찬을 먹었어요`·`절반`, 시험 복약 회차 `안 먹었습니다` |7.5시간/밥과 반찬/50%/미복용 검토. 자동 저장 없음. 하루 전체 `먹었어요`는 모두 복용으로 추론하지 않음 |
| M08 | `삼천 걸음 아니고 사천 걸음`, `먹은 것 같아요`, 다른 날짜, 단위 없는 수치 | 모호함/날짜 불일치를 임의 기록하지 않음. 수정 또는 손 입력 가능 |
| M09 | 음성 미지원·서비스 사용 불가 환경 | 작동 중으로 오표시하지 않음. 기존 손 입력으로 기록 가능 |

객체 존재·onstart/onend 모의 통과는 실제 허용/인식/마이크 종료 증거가 아니다. 음질 문제가 남으면 기기 설정과 마지막 조작·오류를 보고하고 수정 후 재시험한다. 녹음 원본·민감한 건강 내용·키는 회신하지 않는다.

결과 양식: `SHA / 기종 / iOS / 실행 형태 / M번호 / 실제 소리·인식 여부 / 마지막 버튼 / 오류 문구 / 저장 전후 값 / 통과·실패`.

## 운영 배포 관문

최신 지시에 따른 준비는 main 병합→**main의 동일 SHA** CI→배포 SHA 인계다. Render 실제 배포와 health0.8.1/schema8·정적 파일·합성 기록 확인, 위 실제 마이크 인수 결과는 각각 따로 기록한다. main 반영이나 Live 표시만으로 실기기 통과로 바꾸지 않는다.
