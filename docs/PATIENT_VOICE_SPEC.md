## 지원 범위와 경계

환자 모바일 웹을 변경한다. 기존 의료진 데스크톱·Node24/SQLite API·iOS HealthKit/Android Health Connect 연결 앱은 유지한다. 신규 음성 인식은 Web Speech API의 SpeechRecognition/webkitSpeechRecognition, 읽기는 speechSynthesis의 한국어 목소리를 사용한다. 브라우저·OS·권한·설치 음성·네트워크에 따라 사용 불가할 수 있다. API 존재는 실제 인식 성공의 증거가 아니다. 새 유료 API/서버 키는 필요하지 않다. 브라우저 제공자에게 음성이 전송될 수 있음을 시작 전에 알리고 동의를 받는다. 앱 서버에는 녹음/미확정 원고를 보내지 않는다. 실제 네이티브 음성·백그라운드 예약/푸시·서버 음성 인식은 후속 결정이다.

## 데이터·음성 계약

- 기존 API/schema6 유지. 음성은 환자가 확인한 입력 방법이며 기존 환자 자기보고로 저장한다. 인식 원문/오디오/확인 전 초안은 DB·로그·브라우저 영구 저장소에 보관하지 않는다. 기존 revision·clientSubmissionId·사진/환자 권한 검사는 그대로다.
- 지원: 걸음(0~100000 정수+걸음), 수면(0~24시간, 시간/분→기존0.1시간 반올림·표시), 몸무게(기존 UI20~300kg/0.1kg), 날짜(오늘/어제/명시 YYYY년M월D일·ISO, 미래 불가), 일일/약별 복약의 명확한 상태, 건강 메모/메시지, 수동 식사 유형·명확한 섭취비율. 모든 필드는 개별 선택·확인한다. 사진 AI 초안의 음식 유형을 음성으로 덮어쓰지 않는다.
- 모호한 수치/단위 없음/여러 값/부정문 충돌/현재 입력 날짜와 다른 날짜 수식은 거부하고 정정·수동 입력을 안내한다. 약 이름으로 약을 찾거나 용량·처방을 생성하지 않는다. 약 회차는 열린 폼의 환자/날짜/약/시간으로 고정한다.
- 인식 시작 때 환자·폼·날짜·필드·회차·세대 토큰을 고정하고 결과·적용 직전 재검사한다. 닫기/환자·날짜·화면 변경/세션 만료/페이지 숨김은 인식을 중단하고 지연 결과를 무효화한다. 녹음 중 TTS 중단, TTS 중 녹음 시작 시 이전 안내 취소. 시작 응답10초·전체 시도25초·명시 중지 후2초의 별도 제한을 둔다. 콜백이 없어도 종료 처리를 멱등 수행하고 늦은 콜백은 무효화한다. 미지원은 활성 녹음처럼 표시하지 않는다.
- 할 일의 식사 완료는 ‘오늘 식사 기록이 있음’이며 하루3끼/전체 섭취 완료가 아니다. 걸음/수면의 실제0은 기록이다. 약은 당일 pending 중 현재 KST 시각 이전의 회차만 확인 대상으로 삼으며 future는 예정, missed/unknown은 이미 보고한 상태다. 약 일정 조회실패는 완료/미복용으로 추론하지 않는다. 미등록 일정은 약을 먹으라고 말하지 않는다. 기관이 승인한 필수 수집계획이 없어 일반 기록 제안으로 표시한다.
- 앱 내 할 일은 정규 화면 조회 및 홈에서60초 간격 안전한 GET 갱신으로 재평가한다. 저장/초안/마이크/세션잠금/숨김 중 갱신·자동 음성 금지. 날짜 변경·조회 실패·오래된 자료는 다시확인 안내, 과거 자료로 당일 알림 금지.
- 반복알림은 사용자 선택 시 화면이 열려 있을 때만 최소15분 간격. 네이티브 Notification은 사용자 클릭으로 권한 요청·거절 반복요청 금지, 생성 미지원이면 앱 내 대안. 제목/본문은 일반 기록 안내로 제한하고 이름·약명·수치 제외. 숨김/잠금/화면 종료의 백그라운드 전달은 구현하지 않는다.
- 비민감 설정(음성 on/off, 반복알림 on/off)만 localStorage에 보관하며 저장 실패 시 메모리로 동작한다. 인사/알림 중복 억제 키와 건강 내용은 탭 메모리에만 둔다. 종료/환자 변경 시 음성 초안 삭제. 운영 응답/알림 시간·실기기 지원 표는 검증 보고서에 구분한다.

## 추가 지시 COM-04 / QA-MENU-01 (2026-10-24, 구현 전)

기존 환자 음성 개발을 유지하면서 공지·양방향 메뉴 검증을 추가한다. 로컬 실제 브라우저의 기본 작성→공지 저장은 status=draft로 저장되어 환자 수신0, 상태를 published로 바꿔 저장하면 수신·새로고침 보존 성공을 확인했다. 공개 서비스의 실제 원인으로 단정하지 않는다. 기존 ‘공지 저장’ 레이블은 게시 성공과 임시 저장을 구분하지 못하므로 상태별 명시 버튼·대상·지속 결과·환자 미리보기/재확인 경로로 수정한다. 실패/재시도/원고 보존도 검증한다.

전체 공지는 전체 대상 권한을 가진 의료진만 게시한다. 제한된 환자 배정 계정에는 전체 환자 방송 권한을 자동 부여하지 않으며 서버와 UI에서 차단한다. 환자별/기관별 공지 기능은 이번에 임의 추가하지 않는다. 환자별 전달은 기존 개별 메시지를 사용한다. 실제 기관 분리는 현 데이터 구조에 없어 보장하지 않는다.

공지의 응답 손실 후 재전송 중복을 방지하기 위해 선택 UUID clientRequestId와 행위자별 요청 해시/저장 응답 영수증 테이블을 추가한다. 같은 키/같은 요청은 이전 결과, 같은 키/다른 요청409, 변경 요청의 revision 충돌409 유지. 기존 API는 호환한다. 이 추가 테이블로 목표는 v0.8.0/schema7로 변경하며 기존 환자 기록은 보존한다.

의료진10개·환자6개 메뉴의 주요 조작, 공지 게시/수정/보관→환자 표시, 식사/약/측정→의료진 조회, 대화, 권한/범위, 중복·실패·새로고침은 임시 합성DB에서 실제 Playwright 클릭으로 실행한다. 공개 서비스는 접근 허용 범위에서 버전 조회를 먼저 시도하며 접근 불가를 로컬 성공으로 대체하지 않는다. 사용자 테스트 허용은 실제 공개 서비스의 합성 입력도 포함하나 이번 환경에서 접근이 안 되면 수행했다고 표시하지 않는다. 기존 전체 초기화는 하지 않는다.

### 최종 좁은 화면 배치 보강

공지10건·긴 합성 이름·음성 재생 제한 조건에서 듣기 영역이 기록 버튼을 아래로 밀어내는 회귀를 확인했다. 홈의 듣기/중지 버튼을 헤더로 옮겨 항상 첫 화면에서 찾게 하고 재생 중에는 중지 버튼으로 교체한다. 서브 화면은 기존 동일 위치 X를 유지한다. 홈 인사는 짧게, 이름은 환자 문맥에서 표시한다. 한국어 목소리가 없는 곳에서는 자동 재생 시도를 반복하지 않고 직접 듣기 조작 때 설명한다.


## 2026-10-25 음성 입력 신뢰성 보강 계약 (REL-02·REL-07, 코드 변경 전)

P-VOICE-INPUT의 진입·닫기·기존 저장 경로는 그대로다. 인식 시작은 요청 당시 환자/날짜/항목/폼 세대에 묶이고, `requesting → listening → stopping → review|idle|error` 상태를 사용한다. 인식기별 실행 ID와 활성 시도 객체로 이전 인식의 onstart/onresult/onerror/onend를 무효화한다. onstart가 빠지거나 onend가 먼저 와도 제어가 잠기지 않으며 종료 후 중복·늦은 이벤트는 원고/버튼/메시지를 바꾸지 않는다. 종료한 실행에서 늦은 onstart가 오면 해당 예전 인식기에만 다시 abort를 요청하여 새 인식기를 방해하지 않는다.

시작 응답 제한10초, 전체 시도25초, 사용자가 중지를 누른 뒤 결과 대기2초를 독립 타이머로 둔다. 모든 종료는 타이머 해제·실행 무효화·브라우저 abort 요청·UI 복원을 공통 처리한다. 종료 제한 도달은 ‘응답을 기다리다 중단했어요’로 알리며 실제 기기 마이크 종료 성공을 자동 검증 결과로 단정하지 않는다. 숨김/세션 만료/다른 음성 안내/날짜 변경도 같은 정리 함수를 이용한다. 마이크를 기다리는 중에도 중지·닫기·수동 입력 경로가 남는다. abort가 예외를 던지면 해당 인식기의 `stopUnconfirmed` 상태를 남기고 ‘마이크 꺼짐’ 대신 종료 확인 필요를 표시한다. 수동 편집·검토·저장 경로는 유지하되 새 마이크 시작과 자동 음성 안내는 보류한다. 브라우저의 마이크 표시가 계속 켜져 있으면 탭을 닫거나 사이트의 마이크 권한을 끄도록 안내한다. 인식기를 닫아 패널이 없어도 이 안내를 일반 화면에 유지한다. 해당 옛 인식기의 실제 onend/onerror만 미확인 상태를 해제하며, 다른 새 인식기의 종료나 패널 재열기로 임의 해제하지 않는다. 오래된 종료 이벤트가 초안을 바꾸지는 않는다.

이전 편집 원고 `previousTranscript`와 새 시도 확정 결과 `attemptTranscript`를 분리한다. 다시 말하기는 이전 원고를 지우지 않는다. 새 인식의 정상 종료 또는 명시 중지/시간 제한에서 확정 결과가 있으면 검토할 새 초안으로 제시한다. 오류·확정 결과 없음·시작 실패는 이전 원고를 복원한다. 이전 원고가 없는 첫 시도에서 확정 결과를 받은 뒤 오류가 나면 그 확정 결과는 검토용 초안으로 남기며, 중간 결과는 남기지 않는다. 중간 결과는 들리는 동안만 표시하며 확정 결과로 승격하지 않는다. 새 시도·원고 수정은 이전 검토/확인 체크를 해제한다. 어떤 경로도 자동 적용/저장을 실행하지 않는다. 초안/음성은 메모리만 사용하고 로그·영구 저장소에 보관하지 않는다.

`voiceInputExamples(field)`가 필드별 허용 예문의 단일 기준이다. 패널 예문과 해석 실패 문구는 같은 예문을 사용한다. `medicationStatus`는 하루 전체를 뜻하므로 ‘모두 먹었어요’만 전체 복용으로 확인하고 모호한 ‘먹었어요’를 허용 예문으로 제시하지 않는다. `status`는 현재 약 회차이며 일부 복용을 taken으로 바꾸지 않는다. ‘걸음을 걸었어요’, ‘약을 먹었습니다’, ‘밥과 반찬을 먹었어요’ 등 의미가 바뀌지 않는 한정 조사/어미를 수용한다. 섭취비율 ‘절반’, ‘모두’의 안내와 실제 해석을 일치시킨다. 부정·모름·여러 수치·상충 문장·다른 날짜를 버리는 일반 문자열 치환이나 추측은 금지한다.

인수조건: 종료 이벤트 누락/중복/역순, 중지 직후 늦은 결과, 첫 시작 실패, 허용 거절·재시도, 오류 난 다시 말하기의 이전 원고 보존, 중간 결과만 수신, 폼/날짜/환자 경계, 권한 미지원 수동 대안, 예문 전수 해석 및 부정문·단위/범위·모호함 거부. 브라우저 이벤트 모의 통과는 실제 아이폰 Safari 음성 인식 통과가 아니다. 최신 사용자 지시에 따라 최종 커밋의 main 병합·CI·배포 준비를 진행하되 실제 마이크 인수 미완료를 명시한다.
