# 클라이언트 연결·사진 준비 신뢰성 계약

2026-10-25 KST. REL-01/A01과 REL-05/A09의 구현 전 계약이다. 적용 파일은 `public/session.js`, `public/patient-image.js`이며 환자 초기 재시도 버튼과 세대 제어는 `patient.js`에서 연결한다. 구현·자동 검사·실제 iPhone·배포 완료는 각각 별도로 기록한다.

## 세션 HTTP

- 세션 조회·데모 역할/환자 전환·로그아웃·초대 연결은 헤더 수신뿐 아니라 JSON 본문 읽기를 포함하여 요청당 20초 상한을 적용한다. `AbortController`로 실제 전송을 취소하고 시간제한 경합도 종료하여 무한 대기를 막는다.
- 시간초과는 `code=session_timeout`, 쉬운 한국어 재시도 안내로 반환한다. 네트워크 단절은 `session_network`, 명시 취소는 `session_cancelled`이다. 서버가 돌려준 권한/업무 오류는 기존 의미를 유지한다. 자동 재전송·자동 demo 전환은 하지 않는다.
- 실패한 요청은 현재 세션·계정·CSRF 값을 새 성공 응답으로 간주하지 않는다. 결과를 받은 뒤에만 `sessionState`를 갱신한다. POST 시간초과는 서버에서 전혀 처리하지 않았다는 뜻이 아니다. 로그아웃 실패 조작은 잠금을 해제하고 다시 확인/재시도할 수 있다.
- 로그아웃 응답만 유실되었거나 세션이 이미 만료되어 `POST /api/auth/logout`가 401을 돌려주면 서버에 활성 세션이 없다는 확인으로 처리한다. 재로그인 복구창을 만들지 않고 기존 로그아웃 완료 경로로 이동한다. 다른 API의 401·CSRF 오류403은 기존 세션 복구/거절 의미를 유지한다.
- 같은 계정·역할·환자·권한 확인 후 복구하는 `recoveryIdentity`, 탭별 demo 헤더, Kakao fail closed, CSRF·환자 범위 검증은 변경하지 않는다. 요청 시작 시 받은 외부 취소 신호가 있으면 함께 취소하고 listener/timer를 종료 경로마다 정리한다.
- 인수: 응답 시작 없음·헤더 후 본문 없음 모두 20초 뒤 오류; abort 전달; 네트워크 실패/성공 재시도; 기존 세션 값 보존; 로그아웃 실패 후 재시도; 기존 인증 브라우저 회귀.

## 사진 준비

- 기존 입력/출력은 `preparePatientImage(file) → {imageData, adjusted}`다. 환자 사진·원문은 RAM에만 두며 `localStorage`·로그에 보관하지 않는다.
- 빈 사진·20MB 초과·지원하지 않는 형식은 기존 쉬운 한국어 안내로 거절한다. JPEG/PNG/WebP는 선언 MIME와 파일 signature가 일치해야 한다. HEIC/HEIF는 브라우저 실제 해독 가능 여부에 따라 JPEG로 변환하며 미지원 안내를 제공한다.
- 디코더를 만들기 **전에 최대 1MiB의 파일 앞부분만 읽어** PNG IHDR, JPEG SOF, WebP VP8/VP8L/VP8X의 선언 치수를 검사한다. 가로·세로가 0이거나 8천만 화소 초과이면 `Image`/object URL 생성 전에 거절한다. 지원 형식인데 치수 헤더가 잘렸거나 1MiB 안에서 치수를 확인하지 못하면 해독하지 않고 다른 사진을 요청한다. JPEG의 segment·WebP chunk 길이는 읽은 범위와 전체 파일 길이를 넘겨 참조하지 않는다.
- **5MB 이하 사진도 반드시 실제로 해독하고 가로/세로가 양수이며 8천만 화소 이하인지 검사한다.** 작은 지원 사진은 검사 후 원래 바이트를 그대로 반환하여 AI 초안 hash 계약을 보존한다. 해독 실패·MIME 불일치는 준비 완료가 아니다.
- 헤더 검사는 큰 선언 치수로 인한 불필요한 디코딩을 줄이는 방어다. 8천만 화소 이하 또는 헤더를 통과했다는 이유로 모든 Safari의 메모리 안전을 보장하지 않는다. 애니메이션 WebP는 canvas와 첫 ANMF 프레임의 치수를 검사하지만 전체 프레임의 누적 메모리·디코더 내부 할당량을 제한하지 않는다. HEIC/HEIF 메타데이터의 사전 치수 해석은 아직 지원하지 않으며 실제 해독 후 치수 검사만 적용한다. 브라우저 디코더가 이벤트 루프를 막거나 OS가 탭을 종료하면 JavaScript의 15초 타이머가 이를 선점하여 중단할 수 없다. 실제 iPhone의 고해상도·애니메이션·HEIC 메모리 동작은 별도 검증 대상이다.
- 브라우저의 이미지 디코더가 EXIF 방향을 적용한 이미지로 표시/변환한다. 변환이 필요하면 기존 긴 변 2048px, JPEG 품질 0.88/0.74/0.6과 5MB 제한을 유지한다. 이미지 디코딩·파일 읽기·각 JPEG 변환은 각각 15초 제한으로 종료하고 실패 시 다시 선택하도록 한다.
- object URL과 디코딩 자원·timeout·FileReader 이벤트는 성공/실패 모두 정리한다. 늦은 성공으로 앞선 오류가 준비 완료로 바뀌지 않는다. 사진 교체/닫기 세대 폐기는 기존 호출자가 유지한다.
- 인수: 정상 소형 PNG/JPEG/WebP 바이트 보존, 작은 깨진 이미지·MIME 불일치·빈 사진·과대 화소 거절, 실제 과대/0 치수·잘린 PNG/JPEG/WebP 파일이 Image 생성까지 가지 않는지 확인, 필요 변환 JPEG 출력/용량, EXIF 방향, 디코딩 이벤트 누락 종료/URL 회수. iPhone 실제 카메라·사진함·HEIC 검증은 Chromium 검사와 구분한다.
