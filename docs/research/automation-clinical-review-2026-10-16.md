# HomeCareAI 자동화 기능의 임상·운영 요구사항 검토

작성 기준: 2026년 10월 16일, 한국 시간. 코드 변경 없는 설계 검토.

## 1. 범위와 결론

새 요구의 전제는 **환자 모바일웹과 의료진 PC 데모가 이미 배포되어 있다**는 것이다. 이는 이번 작업에서 전달받은 최신 현황이며, 이 검토에서 배포 사이트·API·실사용자 자료를 직접 점검했다는 뜻은 아니다. 기존 전략의 “HTML 세 파일뿐”이라는 과거 현황을 현재 사실로 재인용하지 않는다. 외부 메시지 발송, DB 초기화, 실사용자 자료 변경은 하지 않았다.

권고는 **식사 AI 초안 → 사용자의 식사·섭취 확인 → 근거가 표시된 추정 기록**, **의료진이 관리하는 복약계획 → 회차별 자기보고 → 예외 확인**, **출처를 보존한 활동·수면 수집 → 중복 제거 → 관측 가능한 범위의 추세**이다. 자동화의 목표는 입력·정리 부담을 줄이는 것이며, 사진이나 센서가 알려주지 않는 사실을 확정하는 것이 아니다.

원문은 노인의 최소 행동, 4주 수집, 영양·복약·낙상·건강위험이라는 목표와 Feasibility → Validity → Prediction 순서를 제시한다.[D2 pp.1,3–5] 새 기능도 이 목표를 유지한다. 아래 통과조건은 **개발·검토를 위한 제안**이며 이미 달성한 성능이나 검증된 임상 절단값이 아니다. 첨부 문서는 검토 자료로 다루었고 외부 행동의 지시로 실행하지 않았다.

## 2. 공통 기록 원칙

| 구분 | 제품과 데이터가 지켜야 할 의미 |
|---|---|
| 관찰과 추정 | 사진, OCR 원문, 센서 원기록, AI 추정, 환자 확인, 의료진 검토를 분리한다. 한 가지 “확인 완료” 상태로 합치지 않는다. |
| 입력 주체 | 환자·보호자·의료진·자동 수집의 출처를 남긴다. 보호자 입력은 환자의 건강기록에 연결되지만 보호자의 기기 활동으로 대체하지 않는다. |
| 대상과 시점 | 참여자, 관측 시점, 기록·수정 시점, 적용되는 처방계획 버전을 구별한다. 과거 사진을 오늘 업로드해도 오늘 식사·복용으로 자동 분류하지 않는다. |
| 불확실성 | `모름`, `보고 없음`, `분석 불가`, `관측 없음`, `실제 0`은 다르다. 알 수 없는 수치를 0으로 저장하거나 임의로 채우지 않는다. |
| 정정 | 원자료·변경 사유·변경자·버전이 남아야 한다. AI 재분석이나 뒤늦은 동기화가 사람이 확인한 사실을 조용히 덮어쓰지 않는다. |
| 완료 | 기기 내 보관, 서버 저장, AI 분석 완료, 사용자 확인을 서로 다른 상태로 표시한다. 사진 업로드 성공을 섭취 확인 성공으로 표시하지 않는다. |
| 후속 행동 | 자료 부족이나 단일 이상치가 곧 진단·처방 변경·낙상 경보가 되지 않는다. 임상 경보는 담당자·검토 간격·대응 절차와 별도로 검증한다. |

## 3. 식사사진 AI: 확인을 거쳐 섭취 기록을 만든다

### 3.1 요구 흐름

1. **촬영·등록:** 식사 날짜/시점, 식전·식후 여부, 촬영자, 공동 반찬 여부를 필요한 수준에서 확인한다. 촬영자의 스마트폰 시각과 식사 시각이 다를 수 있다.
2. **사진 분석:** 음식 후보와 사진에서 확인할 수 있는 특징을 AI 초안으로 만든다. 가림·흐림·복합음식·분량 불명·남긴 양 미상은 명시한다. 사진이 부족하면 재촬영 또는 수동 기록 경로를 제공한다.
3. **환자·보호자 확인:** “이 음식이 맞나요?”와 “얼마나 드셨나요?”를 최소 조작으로 확인한다. 음식명 수정, 가정용 분량 단위, 대략적인 섭취 비율, `잘 모르겠어요`가 가능해야 한다. 모든 항목을 문서형 입력으로 강요하지 않는다.
4. **섭취 기록 생성:** 확인된 음식/분량/섭취비율과 영양 DB 매핑을 이용해 결정론적 계산을 수행한다. 분량을 확인할 수 없으면 음식·섭취 자기보고만 저장하고 영양량은 산출 불가 또는 한계가 표시된 추정으로 남긴다.
5. **의료진 화면:** `사용자 확인 섭취 기록`, `AI 영양량 추정`, `영양사 참조평가`를 별도로 표시한다. 확인되지 않은 초안은 확정 섭취 합계에 포함하지 않는다.

**중요:** 사용자가 “맞아요”를 눌렀다는 것은 식사에 대한 자기보고가 확인되었다는 뜻이다. 영양량의 정확성이나 영양상태가 임상적으로 검증되었다는 뜻은 아니다. 단백질·열량은 끝까지 추정값과 참조평가를 구별한다.

### 3.2 필수 경계

- 사진만으로 음식의 실제 중량, 조리유·소스·재료 비율, 제공된 양 중 먹은 양, 공동 반찬에서 개인이 먹은 몫을 확정하지 않는다. 식전·식후 사진도 이러한 불확실성을 완전히 제거하지 못한다.
- 하루 한 끼 사진은 그날 전체 영양섭취를 대표하지 않는다. 화면은 `기록된 식사의 추정 합계`와 관찰 범위를 표시하고, 미기록 끼니를 0으로 계산하지 않는다.
- 음식·분량을 사용자가 수정하면 기존 AI 영양량을 그대로 두지 않는다. 계산을 다시 수행하고 사용한 영양성분 DB·매핑·계산 버전을 보존한다.
- 모델이 스스로 출력한 확신도 숫자는 검증된 정확도와 다르다. 보정되지 않은 “정확도 95%” 같은 수치를 환자에게 제시하지 않는다.
- 낮은 섭취량 추정으로 영양불량을 확진하거나 고단백 식단·보충제 등을 자동 처방하지 않는다. 신장질환, 연하곤란 등 개별 맥락을 모르는 상태의 자동 권고는 본 기능 범위에서 제외한다.
- 식사 AI의 직접 참조는 섭취량을 독립적으로 확인한 영양사 분석이다. Prealbumin은 단백질 섭취량의 정답이 아니며 임상 연관성을 탐색하는 보조자료로 둔다.[D1 문단26; D2 p.3; S §§2,6–7]

### 3.3 초기 승인기준

- 사용자 확인 없이 AI 초안이 확정 섭취량·일일 섭취 합계로 승격되지 않는다.
- 음식/분량/섭취비율의 필수 의미가 불명확하면 정확한 단백질 g·열량 kcal를 확정 수치처럼 표시하지 않는다.
- 수정 후 재계산, 분석 실패, 중복 업로드, 다른 환자로 화면 이동, 뒤늦은 AI 응답에 대한 기록 일관성이 검증된다.
- 영양사 평가 표본에서 음식 유형·분량·기기·대리 입력·분석 불가 사례를 포함해 오차·편향·평가 불가율을 보고한다. 허용오차 수치는 임상 용도와 참조평가 방법을 정한 뒤 사전 합의한다. 임의의 AI 정확도 목표를 여기서 선언하지 않는다.

## 4. 약 사진은 약물정보 후보를 만드는 자료다

### 4.1 서로 다른 사진의 용도를 구분한다

| 사진 유형 | 가능한 보조 기능 | 확정할 수 없는 사실 |
|---|---|---|
| 처방전·약봉투·약품 상자 | OCR 원문 추출, 약명·규격·용법 후보, 확인이 필요한 부분 표시 | 현재 유효한 처방, 실제 조제 내용·복용, 환자의 현재 복용계획 |
| 포장된 약·블리스터 | 표시·코드 등 읽을 수 있는 정보와 제품 후보 제시 | 대상 환자의 정확한 복용량·시간, 남아 있는 약의 실제 사용 여부 |
| 낱알·분할정·여러 약이 섞인 사진 | 재촬영 안내, 식별 단서·후보 제시 또는 식별 불가 판정 | 외관만으로 약의 성분·함량·제형을 확정, 복용 안전성 판단 |
| 복용 전후 사진 | 해당 시점에 찍은 보조 기록 | 삼켰다는 사실, 정확한 용량, 의도한 약을 실제로 복용했다는 증명 |

약 사진이나 OCR 결과는 `검토 후보`로 저장한다. 확인되지 않은 약명·규격·용법을 활성 복약계획에 자동 추가하지 않는다. 사람이 확인해도 그 근거가 과거 처방전인지 현재 처방인지 기록해야 한다. “사진으로 복용 인증”이라는 기능명은 피하고 `약 사진 첨부` 또는 `복용 자기보고의 참고 사진`으로 표현한다.

OCR에서 특히 구분할 필드는 제품/성분, 함량, 제형, 1회 투여량, 투여량 단위, 경로, 빈도, 시작·종료 시점이다. 예를 들어 `0.5정`과 `0.5 mg`, 제품의 `1정당 함량`과 `1회 복용량`은 별개다. 흐린 소수점, 유사 이름, 오래된 약봉투, 서로 다른 처방기관의 중복약은 의료진 또는 기관이 정한 약물 확인 담당자가 원자료와 대조한다.

**승인기준:** OCR 성공률이 높다는 이유만으로 자동 처방 등록을 허용하지 않는다. 정해진 검증 사례에서 미확인 OCR 후보는 활성 목록·복약 알림·회차별 이행률 계산에 들어가지 않아야 한다. 식별이 불가능한 사진에는 임의의 약명을 채우지 않는다.

## 5. 의료진 약 목록과 회차별 복약 기록

### 5.1 목록·계획·보고를 별도로 관리한다

- **약 목록:** 현재 처방/복용 중인 것으로 확인된 약, 확인 대기 약, 중단 약을 구분한다. 환자나 보호자가 추가한 정보는 의료진 확인 전까지 환자 보고 정보라는 출처를 유지한다.
- **복약계획:** 약·용량·단위·빈도·시간 또는 식사와의 관계, 적용 시작/종료, 필요 시 복용(PRN), 계획의 근거·확인자·버전을 보존한다. `식후`를 모든 약에서 임의의 동일 시각이나 “30분 후”로 변환하지 않는다. 일정이 불명확하면 확인이 필요하다.
- **예정 회차:** 날짜/시간대별로 실제 복용 예정인 약을 묶는다. 환자는 “이번 회차 약”을 보고 한 번에 기록할 수 있고, 일부만 복용한 경우에는 해당 약을 선택해 예외를 남긴다. 다약제 환자에게 약마다 반복 조작을 강제하지 않는다.
- **복약 보고:** 실제로 복용했다고 보고한 시각, 입력 시각, 입력자, 보고한 양/상태, 이유·메모를 해당 회차와 연결한다. 과거 기록 입력도 허용하되 시각을 자동으로 현재 복용으로 바꾸지 않는다.

### 5.2 상태의 의미

| 상태/항목 | 기록할 의미 | 해서는 안 되는 변환 |
|---|---|---|
| 예정·아직 보고 없음 | 앞으로의 일정 또는 보고되지 않은 회차 | 시간이 지났다는 이유만으로 미복용·거부로 확정 |
| 복용했다고 보고 | 환자/보호자가 특정 회차를 복용했다고 기록 | 센서나 사진으로 복용이 객관적으로 증명되었다고 표시 |
| 일부 복용 | 어느 약 또는 얼마를 복용했다고 보고했는지 | 전체 회차 완료로 계산 |
| 미복용 | 복용하지 않았다고 명시적으로 보고 | 이유를 자동으로 거부·비협조로 추정 |
| 거부 | 환자가 해당 회차 복용을 원하지 않았다고 명시적으로 보고한 이유 | 전체 치료 거부나 인지능력 판단으로 확대 |
| 의료진 지시 보류 | 확인된 의료진 지시의 근거·시점·기간·대상 약 | 환자가 누른 보류 버튼만으로 처방계획 변경 |
| 보류했다고 보고/확인 대기 | 환자·보호자가 의료진이 보류하라고 했다고 보고했지만 확인 전인 상태 | 확인된 지시처럼 활성 계획에 즉시 반영 |
| 모름·기억나지 않음 | 복용 여부를 답할 수 없는 상태 | 미복용 또는 복용으로 자동 대체 |
| 메모·증상 | 보고 내용과 시점, 확인/연락 필요 여부 | 메모에서 AI가 용량 변경·중단 지시를 만들어 적용 |

`거부`, `잊음`, `약 없음`, `불편해서 못 먹음` 등은 미복용 이유로 표현할 수 있다. 약물 이상반응이 의심된다는 보고는 기관의 연락·대응 흐름으로 연결하되 앱이 독자적으로 중단·증량·보충 복용을 지시하지 않는다. 놓친 약을 나중에 두 배로 먹으라는 자동 안내도 생성하지 않는다.

환자가 의료진 지시 보류를 보고했으나 아직 확인되지 않았다면, 이를 확정 처방 변경으로 처리하지 않는 동시에 기존 알림이 “지금 반드시 복용하세요”처럼 상충하는 복용 지시를 만들지 않도록 한다. `지시 확인 필요`와 기관 연락 경로를 보여주고 확인 상태를 관리한다. 확인 전 임의 재개·중단 판단은 앱이 대신하지 않는다. 미복용 이유는 가능한 범위의 선택 입력으로 두고 이유를 설명하지 않았다고 복용 보고 자체를 막지 않는다.

### 5.3 변경과 예외 처리

- 의료진이 약을 시작·중단·보류·재개하면 적용 시점 이후의 예정 회차를 조정한다. 이전 회차와 당시 계획 버전은 보존한다. 과거 이행률이 현재 처방 변경에 따라 조용히 바뀌지 않게 한다.
- 필요 시 복용(PRN)은 매일 반드시 복용해야 하는 일정의 미이행으로 세지 않는다. PRN 보고를 별도로 수집하며 앱이 적응증·용량 판단을 대신하지 않는다.
- 같은 회차를 환자와 보호자가 다르게 보고하면 마지막 입력으로 무조건 덮어쓰지 않는다. 충돌 상태와 정정 이력을 유지하고 확인하도록 한다.
- “이번 회차 모두 복용”은 실제로 화면에 제시된 활성 예정 약에만 적용한다. 보류·중단·PRN 약이나 확인 대기 OCR 후보를 포함하지 않는다.
- 의료진용 화면은 미복용과 미보고, 확인된 지시 보류를 다른 상태로 보여준다. 메모를 열기 전에 상태만 보아도 이 차이가 드러나야 한다.

### 5.4 복약 지표

1. **보고 완결률:** 예정 회차 중 복용/일부/미복용/모름 등 답변이 기록된 회차 비율. 데이터 수집의 성실도이지 약 복용률이 아니다.
2. **정해진 계획에 대한 복용 자기보고율:** 사전 정의한 분석대상 회차 중 계획대로 복용했다고 보고한 비율. 부분 복용·확인된 지시 보류·PRN·입원·처방 변경 처리 규칙을 별도로 정한다.
3. **알 수 없는 비율:** 미보고·기억나지 않음·충돌 등으로 복용 여부를 해석할 수 없는 비율을 숨기지 않는다.

확인된 보류·중단 회차를 분석대상에서 제외하는 경우에도 해당 근거와 수를 함께 보고한다. 분모를 바꾸어 순응도를 높아 보이게 해서는 안 된다. 이 지표와 MMAS-8 등 설문 간 관계는 분석척도와 사용조건을 정한 후 평가하며 실제 복용을 완전히 확인한 정답으로 다루지 않는다.[D2 p.3; C §§2,5]

## 6. 활동·수면 자동 연동

### 6.1 모바일웹의 현재 역할과 자동 수집의 조건

모바일웹의 촬영·확인·복약보고 흐름은 활용할 수 있다. 그러나 배포된 웹 화면 자체가 HealthKit/Health Connect의 기기 건강기록을 백그라운드에서 읽고 있다는 증거는 아니다. 실제 플랫폼 연동은 지원되는 네이티브 수집 모듈·앱 또는 계약·권한이 확인된 공급자 연동 경로로 구현·검증해야 한다. 웹을 홈 화면에 설치했다는 이유만으로 네이티브 건강 권한이 생긴다고 가정하지 않는다.[D1 표1·2; S §5]

수집 시작 전 환자 기기/웨어러블, 원기록을 생성하는 앱, 해당 환자의 기기 소지 여부, 권한, 최근 실제 기록을 확인한다. 수면 기록원이 없으면 `연동 가능한 수면자료 없음`을 표시한다. 수동 취침·기상 입력을 대안으로 제공할 수 있으나 자동 측정 수면으로 합치지 않는다.

### 6.2 출처와 중복 제거 요구

| 필요한 구분 | 이유와 처리 원칙 |
|---|---|
| 환자와 기기 소유자 | 보호자 폰으로 식사·복약을 입력해도 보호자의 걸음수를 환자에게 연결하지 않는다. |
| 수집 통로와 원 측정원 | HealthKit/Health Connect는 저장·교환 통로일 수 있다. 실제 원기록 생성 앱/기기와 수동 입력 여부도 남긴다. |
| 원기록 ID·버전 | 같은 기록을 재동기화해도 한 번만 집계한다. 단순히 타임스탬프가 같다는 이유로 서로 다른 관측을 삭제하지 않는다. |
| 원 측정값과 일별 요약 | 누적 걸음수와 구간별 걸음수를 혼합해 합산하지 않는다. 갱신된 일별 누적값은 새 걸음수가 아니라 이전 집계의 갱신일 수 있다. |
| 여러 소스의 겹치는 시간 | 시계와 폰의 걸음수, 여러 앱이 복제한 수면 기록을 모두 더하지 않는다. 항목별 우선 소스·겹침 처리 규칙을 고정하고 사용한 소스를 표시한다. |
| 원자료와 파생 합계 | 원자료를 보존한 채 정해진 규칙으로 파생값을 재현한다. 출처 간 중복 여부가 불명확하면 이를 숨기지 않는다. |
| 원기록 정정·삭제 | 지원되는 변경 추적 범위에서 원기록 수정·삭제를 반영하고 영향을 받은 일별 결과를 재계산한다. 지원 한계도 명시한다. |
| 마지막 연결과 마지막 관측 | “방금 연결됨”이 “방금 환자 상태가 측정됨”을 뜻하지 않는다. 마지막 성공 동기화와 최신 실제 관측 시점을 각각 표시한다. |

모든 출처를 일률적으로 합치는 것보다, 초기에는 항목별 신뢰할 수 있는 주 소스를 지정하고 대체 출처를 표시하는 편이 해석 가능하다. 출처 우선순위·겹침 처리·하루 경계 규칙은 버전으로 관리한다. 데이터원이 바뀐 전후의 변화는 환자 상태 변화와 혼동될 수 있으므로 의료진에게 전환점을 보여준다.

### 6.3 수면과 활동의 임상 해석

- 수면 중 `침대에 있었던 시간`, `잠든 것으로 추정된 시간`, `각성`, `수면 단계`, `낮잠`은 다른 항목이다. 수면 단계와 전체 수면 세션을 중복 합산하지 않는다. 단계가 없다고 수면이 없었다고 판단하지 않는다.
- 자정을 넘는 수면은 시작·종료 시각을 보존하고 연구에서 정한 기준일(예: 기상일)에 요약한다. 시간대 변경은 실제 경과시간과 날짜 집계에 반영한다.
- 느린 보행, 보행보조기, 기기 미소지, 충전·배터리 문제는 관측에 영향을 준다. 걸음수 감소를 곧 낙상 발생·기능 악화로 판정하지 않는다.
- 자료가 없는 날은 걸음수 0·수면 0시간으로 바꾸지 않는다. 권한 상태와 자료 부재를 OS가 구분해 주지 않는 경우에는 원인을 추정 확정하지 않는다.[S §5]
- 웨어러블 수면값만으로 불면증·수면장애를 진단하지 않는다. 자동 수집은 측정값의 접근 방법이며 임상 정확성 자체를 보장하지 않는다.

**승인기준:** 실제 포함할 기기/OS에서 기록 생성→수집→서버 저장→일별 집계→의료진 조회→분석 내보내기를 확인한다. 중복 재수집·다중 소스·권한 변화·기기 미소지·날짜 경계·원기록 정정에서 집계 의미가 보존되어야 한다. 전체 예정 추적일 대비 자료 확보율과, 기술적으로 수집 가능한 조건에서의 성공률을 별도로 보고한다.

## 7. 우선 개발 단계와 단계별 통과조건

| 단계 | 우선 구현/확인 | 다음 단계 조건 |
|---|---|---|
| 0. 기록 계약 확정 | 환자/보호자/의료진 역할, 환자 매칭, 약 목록·계획·회차, AI 초안/확인/참조의 구분, 데이터 출처·정정 규칙 | 화면 상태와 저장 의미를 임상·기술 담당자가 같은 뜻으로 설명할 수 있음 |
| 1. 확인 가능한 수동 흐름 | 의료진 약 목록·회차별 보고·거부/보류/메모, 음식·섭취 수동 확인, 실제 저장·재조회·정정 | 환자 전환·중복·실패·충돌·처방 변경에서 기록 일관성 확보; 모름/미보고와 부정 결과 구별 |
| 2. 식사 AI 초안과 약 OCR 보조 | 식사 후보·확인·재계산, 약 OCR 검토 대기, 분석 실패·재촬영 | AI 후보의 무단 확정 없음; 불명확한 약 규격/용법이 활성 일정으로 진입하지 않음; 영양사 평가 계획 확정 |
| 3. 실제 활동·수면 연결 | 소수 대표 기기로 연동 검증 후 포함 기기 확대, 원출처·중복·변경 반영 | 실제 기록과 파생 합계의 대응 확인, 자동/수동·관측 없음 구별, 의료진의 출처 확인 가능 |
| 4. 대상자 사용성·운영 평가 | 승인 범위의 노인/보호자 사전시험, CRC 누락 대응, 브리핑 평가 | 도움 필요 정도·완료 시간·오입력·포기·지원 업무량을 확인하고 주요 오류 수정 |
| 5. 4주 연구와 후속 예측 | 버전을 고정한 수집, 독립 참조평가, 탈락·누락·추정 실패 보고 | 실행가능성과 측정결과 확인 후 예측 확장 여부 결정; 소표본으로 확증 성능을 선언하지 않음 |

단계 3의 기기·API 기술검증은 단계 1과 병렬로 시작할 수 있다. 그러나 “자동연동”으로 사용자에게 제공하는 것은 실제 경로 검증 후다. 이미 동작하는 기능은 증거를 확인해 재사용하며 데모를 다시 만드는 것 자체를 목표로 삼지 않는다.

임상 수집 전에는 연구계획·동의 범위·권한·보관·공급자 처리 조건과 실제 기능이 맞아야 한다. 일일 1버튼 자기보고에서 회차별 기록으로 변경하면 부담·평가 지표·분모가 달라지므로 IRB/연구계획 변경 필요성을 기관 절차로 확인한다. 연구 중 AI 모델·영양 DB·약물 매핑·집계 규칙 변경은 이전 결과를 보존하고 연구책임자가 영향과 분석계획을 판단한다.[D1 문단16–29; D2 p.5]

| P4 | 세 약 중 한 약만 안 먹음 | 회차 전체 완료가 아닌 약별 예외와 부분 보고 보존 |

| P6 | 의료진이 오후부터 보류/중단 | 적용 이후 회차만 조정, 과거 회차·계획 버전·통계 근거 보존 |

| S1 | 보호자가 자기 폰으로 환자 보고 | 보호자 걸음수가 환자에게 연결되지 않음 |

| S3 | 같은 원기록 재동기화·누적값 갱신 | 중복 증가 없이 원기록·파생 합계 갱신 |
| S4 | 수면 세션과 단계·침대시간이 모두 옴 | 겹치는 시간을 중복 합산하지 않고 개념별 표시 |
| S5 | 수면 측정원 없음·앱 권한 변경 | 0시간으로 대체하지 않음; 판별 가능한 상태만 표시 |
| S6 | 자정 통과 수면·시간대 변경 | 실제 경과시간과 정의된 날짜 귀속 유지 |
| S7 | 원기록 정정·삭제·출처 전환 | 지원되는 변경을 반영하고 영향을 받은 집계/추세 재계산 또는 한계 표시 |
| X1 | 환자 A 분석 중 B 화면으로 전환 | A의 지연 응답·메모·사진·복약 상태가 B에 나타나지 않음 |
| X2 | 오프라인 기록 후 재전송·더블탭 | 한 번만 저장, 저장/대기/실패를 정확히 표시 |
| X3 | 정정·AI 재분석·의료진 확인이 동시에 발생 | 사람의 확인이 조용히 소실되지 않으며 충돌·이력을 추적 가능 |
| X4 | 보호자 위임 철회·다른 환자 ID 접근 | 권한 밖 조회·수정 차단, 캐시·알림에 다른 환자 자료 노출 없음 |

출시 검토에서는 이 시나리오 중 환자 혼합, 무권한 접근, 미확인 약물의 활성화, 확정 자료의 조용한 소실과 같은 중대한 결함이 해결되지 않은 상태로 임상 수집을 시작하지 않는다. 이는 개발 통과조건이며 임상 정확도 “100%” 주장과 다르다.

## 9. 의료진과 연구팀이 확인할 산출물

1. 식사 초안/섭취 확인/영양 추정/참조평가의 화면 문구와 상태 정의.
2. 약 목록·계획·회차·보고·보류/중단의 의미, 적용 시점, 수정권한·충돌 규칙.
3. 복약 지표의 분자·분모와 PRN·보류·모름·미보고·계획변경 처리표.
4. 실제 활동·수면 수집 경로, 환자·기기 연결, 원출처·중복·날짜 집계·변경 추적 규칙.
5. 환자·보호자 사용성 평가와 CRC/의료진 지원 업무량, 누락/임상 확인의 담당 흐름.
6. 식사·약 OCR·센서 측정의 참조평가 계획과 버전 고정·변경관리 문서.
7. 위 시나리오의 실행 결과와 남은 제한. 결과를 보기 전에는 “자동복약 확인”, “정확한 영양섭취”, “수면 자동측정 완료”라는 성과 문구를 확정하지 않는다.
