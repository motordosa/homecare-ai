# 부록 B. 의료진 화면 상세 감사

작성일: 2026-10-23. 기준 저장소: `motordosa/homecare-ai`, 커밋 `4068c3cbf9a7dec9afe99035de13cb8b04d401e5`, v0.6.1. 본 문서는 **조사·계획 제안**이다. 실제 앱 코드·활성 계약·운영 DB를 변경하지 않았다. 화면 ID는 `docs/SCREEN_SPEC.md`의 기존 ID를 사용하며, 새 화면은 반드시 **제안**으로 표시한다. 외부 지침의 근거 검토는 통합 보고서에 별도 수록한다.

## 1. 조사 범위와 확인 수준

- 저장소의 의료진 UI, 서버 라우트, 인증, 데이터·분석 모듈과 기존 기획 계약을 정적 검토했다.
- 별도 임시 DB와 로컬 Chromium(1440×1000)에서 복약 계획 입력 후 Escape 동작, 환자관리 화면의 일부 텍스트 크기를 실제 계측했다. 운영 서버에 자료를 입력하거나 초기화하지 않았다.
- 별도 임시 DB에서 ‘오늘 약별 회차 보고만 있는 환자’의 요약 지표를 재현했다. 임시 서버와 DB는 종료·정리했다.
- 실제 의료진·보조 인력 대상 사용성 실험, 전체 WCAG 적합성 평가, 부하 시험은 수행하지 않았다. 아래 목표값과 화면 구성은 검토가 필요한 프로젝트 제안이다.
- `render.yaml`은 저장소의 배포 기본값이며 현재 Render 환경변수가 반드시 같은 값이라고 단정하지 않는다.

### 보존해야 할 기존 강점

현재 데모는 단순한 빈 껍데기가 아니다. 일일 보고의 null과 0 구별, 수동/기기 출처, 약별 계획과 자기보고 구분, pending을 자동 미복용으로 바꾸지 않는 처리, 복약 수정 revision·snapshot, 약 사진과 환자·이미지 해시·유효기간 연결, 사진 첨부 보고의 트랜잭션과 당시 회차 보존이 있다. 규칙 기반 브리핑은 임상적으로 검증된 위험예측이 아니라고 명시하며 자료 부족과 근거를 표시한다. 공지 초안·게시·보관/버전, 메시지 대상 고정·중복 전송 방지·읽음 상태, 의료진 메뉴의 Back/Forward 복원도 구현되어 있다. Kakao 모드의 환자 본인 ACL과 CSRF 검증도 존재한다. 새 기능은 이 동작을 회귀시키지 않아야 한다.

### 직접 재현한 사실

1. **미저장 복약 계획 소실:** 약명 입력 → Escape → 확인창 0회, 모달 닫힘 → 다시 열면 약명 빈값. `clinician-observation.json`에 저장했다.
2. **선택 범위의 작은 글씨:** 환자관리 화면에서 보이는 `p`, `td`, `th`, `small`, `.small-label`, `.subheading` 중 계측된 123요소가 모두 12px 미만, 최소 7px였다. **전체 앱의 모든 텍스트를 측정했다는 뜻이 아니다.** WCAG가 일률적인 최소 글자 크기를 정했다는 주장도 아니다.
3. **약별 보고만 있는 환자의 요약:** `completion={value:0,reportedDays:0,totalDays:7}`, `lastRecordDate=null`, `doseReportedDays=1`, `legacyReportedDays=0`. 현행 분자 정의가 일일·기기·식사만 포함하기 때문이다. ‘아무 보고도 하지 않음’으로 읽히지 않도록 별도 참여 지표가 필요하다.

## 3. 상세 발견과 인수 조건

### C01. 하나의 ‘의료진’ 권한으로 서로 다른 직무를 처리한다

**현행/근거:** `lib/auth.mjs:91`, `lib/auth.mjs:110`은 clinician/patient/pending 중심이며 staff 검사는 clinician 여부다. clinician의 담당 환자·기관 범위나 연구자·보조 인력·시스템 관리자 권한을 따로 모델링하지 않는다. demo의 일반 기능은 공개 합성자료 시험을 위한 별도 예외다. `server.mjs:258`의 복약 계획, `server.mjs:310`의 초기화, `server.mjs:319`의 CSV에도 공통 staff 권한을 쓴다.

**제안:** 화면의 ‘업무 모드’와 서버 권한을 분리한다. 보조 인력은 배정 환자의 입력 지원·자료 확인 요청·승인된 행정 연락을, 의사는 임상 해석·복약 계획 승인·임상 회신을, 연구자는 허용 연구의 비식별 자료·분석을, 관리자는 계정·환경·복구를 담당한다. 다중 직무자는 명시적으로 권한을 합성한다. 기관마다 허용되는 위임 범위는 병원 정책으로 확정해야 한다.

**인수:** 숨겨진 버튼을 직접 API 호출해도 권한 밖 조작이 거절된다. 담당 환자 범위와 기관 경계가 서버에서 적용된다. 모든 임상 승인에는 행위자·역할·시각이 남는다. 관리자라는 이유만으로 임상 승인 권한을 받지 않는다.

### C02. ‘살펴볼 기록’이 처리할 업무로 이어지지 않는다

**현행/근거:** `lib/analysis.mjs:136`은 현재 규칙 해당 사유로 alerts를 계산한다. `public/clinician.js:221`은 첫 3건을 표시한다. 담당자, 확인 여부, 연락 시도, 다음 할 일, 해결 근거를 저장하는 업무 객체는 없다.

**제안:** 미확인 → 확인 중 → 환자 연락/응답 대기 → 임상 검토 요청 → 완료의 작업 큐를 만든다. 위험 규칙 자체와 사람이 처리한 상태는 별도 관리한다. 높은 우선순위의 기계적 생성이 곧 임상 응급 판단이 되지 않게 한다.

**인수:** 4건 이상도 전체 목록에서 발견 가능하다. 확인·연락·종결을 구분한다. 동일 근거의 중복 업무가 남발하지 않으며 근거 자료가 수정되면 업무가 참조한 버전을 알 수 있다. 임상 판단이 필요한 항목을 보조 인력이 단독 종결하지 못한다.

### C03. 사진 복약 보고의 ‘미검토’ 이후 상태가 없다

**현행/근거:** `lib/medication-photos.mjs:31`은 `reviewStatus:'unreviewed'`를 고정 반환한다. `lib/medication-photos.mjs:40`은 날짜별 최신 20건이며 페이지 이동은 없다. `public/clinician.js:330`은 사진·OCR·당시 보고 snapshot을 조회한다. 사진이 실제 복용을 증명하지 않는다는 현재 구분은 적절하다.

**제안:** 원본 자기보고를 바꾸지 않는 별도 검토 이력을 추가한다. 검토자, 상태, 반려/확인 사유, 환자에게 요청한 추가 확인, 검토한 snapshot revision을 남긴다. 보조 인력의 문자 판독 대조와 의료진의 임상 확인은 다른 상태다.

**인수:** 같은 검토 재전송이 중복 기록을 만들지 않는다. 동시 검토 충돌을 드러낸다. 원본 사진 보고와 이후 수정 기록을 함께 추적한다. 20건 초과 기록을 순서대로 조회할 수 있다. ‘검토 완료’는 ‘실제 복용 확인’과 다른 문구다.

### C04. null 보존은 되지만 결측 이유와 자료 품질 업무가 없다

**현행/근거:** `lib/analysis.mjs:22`는 수동값 우선·기기 보완과 항목별 출처를 유지한다. `lib/db.mjs:40`의 일일 기록은 nullable이지만 미측정 이유나 검토 상태는 없고, `public/clinician.js:236`은 주로 기록일 수를 보여준다.

**제안:** 미예정/미측정/기억 못함/거부/기기 연결 오류/늦은 전송/사유 불명의 구분을 추가한다. 기록자, 관측 날짜·시각, 서버 수신 시각, 출처, 수정 여부와 품질 플래그를 항목별로 추적한다. 저활동을 기기 미착용, 식사 미기록을 금식으로 단정하지 않는다. 미착용 시간 같은 원자료가 없으면 ‘착용 여부 불명’이다.

**인수:** 0과 null, 관측일과 수신일이 유지된다. 이유별 필터·확인 요청이 가능하다. 입력 삭제로 기기 값이 다시 나타나는 기존 우선순위를 사용자에게 설명한다. 누락값 자동 0 대체나 근거 없는 추정 보간을 하지 않는다.

### C05. 요약 지표의 구현은 명시적이지만 직관적인 임상·업무 의미와 일부 다르다

**현행/근거:** `lib/analysis.mjs:64`, `:72`의 복약 %는 **기존 일일 자기보고 점수**로 taken=1, partial=0.5, missed=0의 평균이다. 약별 예정 회차의 이행률이 아니다. `:66`, `:73`의 영양은 **식사 기록이 있는 날의 기록된 식사 추정합계 평균**이다. 식사 누락을 포함한 하루 총섭취량이 아니다. `:75` completion은 고정 7일 분모에 일일·기기·식사 날짜의 합집합만 사용하고, 약별 보고는 `:84`에서 별도로 센다. `:127`의 최근 기록일도 약별 보고를 제외한다. 등록 후 2일인 환자도 고정 분모 7을 사용한다. `public/clinician.js:209`의 필터 ‘안정적 기록’은 분석의 ‘규칙 미해당’(`lib/analysis.mjs:99`)보다 건강 안정으로 읽힐 수 있다.

**제안:** 아래 5장의 지표 계약에 따라 전체 보고 참여/영역별 완성도/약별 자기보고를 구분한다. 복약·영양 카드와 표·차트·CSV에 같은 명칭과 분모를 사용한다. 활동·수면의 5000걸음/7시간 목표와 고정 규칙(`lib/analysis.mjs:70`, `:89`)은 개인별 처방 목표와 구별하며 조정 권한·근거 버전을 둔다.

**인수:** 약별 보고만 있는 환자가 ‘아무 보고 없음’으로 표시되지 않는다. 하루 한 끼만 기록한 경우 ‘기록된 1끼 추정합계’라고 읽힌다. 일부 복약 0.5점이 약별 복용률로 전달되지 않는다. 등록일·휴지기간에 따른 분모가 보인다. ‘자료 부족’과 ‘규칙 미해당’을 건강 안정의 진단으로 바꾸지 않는다.

### C06. 임상적으로 비교할 기간과 사건을 함께 선택하기 어렵다

**현행/근거:** `lib/analysis.mjs:49`는 28일 조회·7일 요약, `:123`은 최근 일일 기록 14건/식사 24건, `public/clinician.js:230`은 14일 차트, `:244`는 식사 3건, `:248`은 일일 표 5/14건을 사용한다. 일반 사용자용 공통 기간 조절·사건 타임라인이 없다.

**제안:** 기본 7/30/90일·사용자 지정 기간을 일관되게 적용하고 활동·수면·영양·복약·체중의 공통 날짜 축을 제공한다. 약 변경, 입원, 방문 등은 확인된 출처와 함께 주석으로 관리한다. 여러 차트의 같은 날짜를 연결해 읽되 수집 공백을 선으로 이어 정상 변화처럼 만들지 않는다.

**인수:** 모든 수치의 적용 날짜·자료 개수가 일치한다. KST 일자 경계와 지연 전송 처리가 계약에 맞는다. 전체 이력 접근과 페이지 수가 표시된다. 차트와 상세 표를 왕복해도 선택 환자·기간이 유지된다.

### C07. 기술통계·코호트 연구를 위한 작업 공간이 없다

### C17. 환자 수 확대와 검색·자료 최신성은 별도 검증이 필요하다

**현행/근거:** `public/clinician.js:200`은 전체 환자의 클라이언트 필터·표 렌더 중심이다. `lib/analysis.mjs:51`은 환자별 전체 기간을 읽고 `:134`는 모든 환자 summary를 계산한다. 현재 성능 장애를 부하 시험으로 입증한 것은 아니지만 규모 증가 시 비용이 커지는 구조다. UI의 최근 갱신 시각은 개별 항목의 관측 시각과 다르다.

**제안:** 담당 팀·상태·기간 필터와 저장된 작업 목록, 서버 페이지 이동·일관된 정렬을 도입한다. 원자료 최신성, 마지막 수신, 현재 화면 as-of를 따로 표시한다. 예상 동시 사용자·환자 수·기간·사진 수를 먼저 합의하고 그 조건에서 측정한다.

**인수:** 페이지 사이 환자 중복·누락이 없고 필터가 재현된다. 실제 병원 네트워크와 합의된 합성 부하에서 응답·상호작용 목표를 만족한다. 기록이 오래되었는데 화면만 갱신했다고 ‘최신 건강 자료’로 표시하지 않는다.

### C18. 실제 연구 도입은 데모 설정과 운영 경계를 나누어야 한다

**현행/근거:** 저장소 `render.yaml:12`, `:18`의 기본은 demo 인증과 `/tmp/homecare-data` 저장이다. `public/clinician.js:494`에는 초기화 확인 문구가 이미 존재하며 `server.mjs:310`의 초기화 API는 staff 범주다. 실제 연구 데이터의 보존·복구·역할별 삭제 정책을 제공하는 구성은 아니다.

**제안:** 데모·연구 환경을 분리하고 연구에서는 전체 초기화를 일반 관리 메뉴에서 제거한다. 영속 저장소, 백업·복원, 접근·감사·철회·보유 정책, 데이터 freeze와 버전 이관을 연구 시작 전 체크포인트로 둔다. 무료 데모를 쓰는 현재 목적에 곧바로 유료 운영 전환을 요구하는 제안은 아니다.

**인수:** 사진과 DB의 연결을 포함해 복원 시험이 성공한다. 역할 없는 전체 삭제가 불가능하고 연구 자료의 삭제/철회 정책이 승인된다. 배포·스키마 변경 후 rollback·자료 일치 여부를 검증한다. 공개 합성자료와 실제 연구 참여자 자료가 섞이지 않는다.

## 5. 지표와 연구 데이터의 재현식 계약 초안

다음은 **신규 계약 제안**이며 현행 계산을 이미 변경했다는 뜻이 아니다. 같은 값에 다른 의미를 부여하지 않도록 카드·차트·CSV·분석 모듈이 이 계약을 함께 참조해야 한다.

### 공통 단위·기간

- `N`: 포함 기준을 충족한 고유 환자 수. 환자-일·복약 회차 수와 분리한다.
- `E_i`: 환자 i의 관찰 기간 중 참여·동의·휴지기간·프로토콜을 반영해 보고가 예정된 일수. 전체 참여율의 분모다. 영양·체중 등 영역별 예정 주기가 다르면 `E_i,d`를 따로 둔다.
- `A_i`: 예정일 중 어느 허용 영역이든 보고가 존재한 날짜 합집합. 약별 회차 보고도 포함한다. 전체 보고 참여 `A_i/E_i`; 개별 항목 충실성은 이 값으로 대신하지 않는다.
- `V_i,d`: 영역 d에서 유효한 관측이 있는 예정일 수. 영역별 가용성 `V_i,d/E_i,d`. 분모 0은 해당 없음이다. 기존 `completion=일일·기기·식사 날짜 합집합/7`은 명칭·설명을 유지하거나 위 새 지표와 명시적으로 교체하는 버전 변경이 필요하다.
- 임상 날짜는 KST 기준이다. `observedAt`/해당 일자, `receivedAt`, `reportedBy`, `source`, `revision`을 구분한다. 활동·수면의 현행 수동 우선 규칙을 재현할 수 있게 수동과 기기 원본은 모두 보존한다. 날짜 가용성과 출처 비율을 각 결과 옆에 표시한다.

### 복약

- `D_i`: 관찰 기간에서 유효한 복약 계획에 따라 **평가 시점까지 예정된 회차** 수. 향후 예정 회차, 시작 전·종료 후·프로토콜상 휴약은 제외하되 산정 이유를 남긴다. 필요 시 복용(PRN)은 별도 분모 정책이 있어야 하며 정규 회차에 임의 포함하지 않는다.
- `T_i`: 복용했다고 자기보고한 회차, `M_i`: 미복용 자기보고 회차, `U_i`: 알 수 없음 보고 회차, `P_i`: 아직 보고가 없는 회차. 각 회차의 최종 유효 revision을 사용한다. 상태의 정의가 배타적이면 `D_i=T_i+M_i+U_i+P_i`가 성립해야 한다.
- `R_i=T_i+M_i+U_i`: 보고된 회차 수. **회차 보고율**=`R_i/D_i`; **예정 회차 대비 복용 보고율**=`T_i/D_i`; **복용 여부를 아는 보고 중 복용 비율**=`T_i/(T_i+M_i)`. 세 값은 목적이 다르며 나란히 n/분모·U·P를 보여준다. `T_i/D_i`의 미보고를 실제 미복용이라고 판정해서는 안 된다. 분모 0은 계산하지 않는다.
- 기존 일일 자기보고 점수 `100×(복용일+0.5×일부복용일)/(복용일+일부복용일+미복용일)`는 그 이름과 단위로 남겨야 한다. 약·회차 수를 알 수 없는 ‘일부’가 약별 50% 이행을 뜻하지 않는다. 사진·OCR·환자 확인도 실제 섭취 증명이 아니다.

### 영양·활동·수면과 집단 통계

- 환자 i, 일 t의 `C_it=그날 기록된 식사의 추정 kcal 합계`. 그날 기록된 식사 건수 `m_it`, 빠진 식사 여부/모름, 사진 분석 또는 음식표 출처를 함께 표시한다. `mean(C_it | 기록일)`은 **기록일별 기록 식사의 추정합계 평균**이다. 모든 끼니·간식이 확인되지 않으면 ‘하루 총섭취량’으로 표시하지 않는다.
- 실제 총섭취량에 근접한 연구 지표가 필요하면 식사 완결성·섭취 비율·간식 포함 등 별도 측정 프로토콜과 검증이 선행되어야 한다. 결측 식사를 0kcal로 대체하지 않는다.
- 활동·수면은 `sum(유효값)/유효 관측일 수`와 관측일 수/예정일 수를 함께 제시한다. 기기 출처별 가용일 수와 자기보고 전환일을 표시한다. 낮은 걸음 수가 질환 악화인지 기기 미착용인지는 이 수치만으로 판정하지 않는다.
- 집단 평균은 ‘환자별 평균의 평균’과 ‘모든 관측일을 합친 평균’의 가중이 다르다. 어떤 질문에 답하는지 정한 뒤 산식을 저장한다. 환자 단위 N과 반복 관측 수를 함께 표시하고 반복 관측을 독립 표본으로 간주하지 않는다.
- 분석용 원자료, 정정 반영 자료, 제외 플래그, 최종 동결 snapshot, 분석 설정·코드/라이브러리 버전을 연결한다. p값·차트 PNG만 남기는 것이 재현 가능한 연구 기록은 아니다.

### 우선 검증할 실제 과업

1. 보조 인력이 미기록 환자를 찾아 사유를 확인하고 의료진에게 필요한 항목만 검토 요청한다.
2. 의사가 사진 보고와 기존 계획의 불일치를 확인하고 원본을 보존한 채 검토 결과를 남긴다.
3. 두 환자의 이름이 같을 때도 대상 확인 후 올바른 환자에게만 메시지·계획을 저장한다.
4. 복약 계획 작성 중 전화 응대·Escape·화면 전환·네트워크 실패 이후 작업을 안전하게 이어간다.
5. 7일과 30일 자료를 비교하면서 결측·출처 전환·약 변경을 설명한다.
6. 연구자가 코호트와 기간을 고르고 N·관측일·회차 분모를 설명한 후 범위에 맞게 내보낸다.
7. 문헌 2건을 찾아 실제 PMID/DOI·대상·연구 설계·고령자 적용 한계를 확인한다.

형성 평가에서는 의사/연구자와 보조 인력을 따로 모집해 도움 없는 과업 완료, 소요 시간, 대상 혼동, 숫자 의미 이해, 검토 요청의 적절성, 주관적 부담을 본다. 각 직무 5~8명 수준의 반복 소규모 평가를 출발점으로 제안할 수 있지만 이는 통계적 효과 검증 표본이 아니다. 안전과 관련된 잘못된 환자 조작·권한 없는 임상 승인이 관찰되면 출시 문턱에서 차단하고 재설계한다. 검증 표본에서 오류 0건이 전체 사용자의 위험 0을 의미하지 않는다.

## 7. 보고서 활용 시 구별할 것

- C11과 C05의 약별 보고 사례, C16의 명시 범위는 로컬 재현이다. C12·C17 등은 코드에서 확인한 설계 격차이며 전체 현장 장애를 실측한 결과가 아니다.
- 자료 출처·null·회차 snapshot·공지/메시지 보호·메뉴 이력은 **이미 존재하는 보존 대상**이다. 새로 개발해야 할 항목처럼 이중 기획하지 않는다.
- 문헌 워크벤치·코호트/추론통계·새 직무권한은 **미구현 제안**이다. 현재 데모에서 사용할 수 있다고 안내하지 않는다.
- 본 파일은 외부 가이드 근거를 대신하지 않는다. 통합 보고서에서 각 접근성·임상 사용성·연구 지침의 발행 주체/판본/공식 URL과 연결하고, 강제 표준·참고 가이드·자체 목표를 구별해야 한다.
