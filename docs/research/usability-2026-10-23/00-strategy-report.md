# HomeCare AI 사용자 중심 개선·버전업 전략 보고서

고령 환자 모바일 웹 · 의료진·보조 인력 데스크톱 웹

작성일: 2026-10-23 (한국 시간)
검토 기준: 배포 v0.6.1 / 커밋 4068c3c / DB schema5
문서 상태: **개발 승인 전 제안서. 이번 업무는 조사·진단·계획 수립이며 실제 개발·배포 변경은 수행하지 않았다.**

## 1. 의사결정 요약

가장 먼저 개선할 부분은 **읽기 쉬움, 오늘 해야 할 일의 명확성, 입력을 잃지 않는 동작**이다. 사진 AI와 통계 기능의 수를 늘려도 이 세 가지가 부족하면 고령 환자의 기록 지속성과 의료진의 자료 신뢰도가 개선되기 어렵다.

환자 화면은 ‘기능별 메뉴를 찾아 기록하는 화면’에서 **오늘 할 일을 큰 버튼으로 하나씩 끝내는 화면**으로 바꾸는 것을 권고한다. 의료진 화면은 **환자 관리 업무 / 임상 검토 / 연구 분석**을 구분하되, 같은 환자·기간·출처를 유지하며 오갈 수 있어야 한다. 보조 인력에게는 정리·연락·확인 요청 업무를 제공하고 임상 판단과 복약계획 확정은 기관이 권한을 부여한 전문가가 맡는다.

권고하는 진행 순서는 다음과 같다.

1. **v0.6.2 — 기본 사용성과 입력 안전:** 글자·대비·터치 영역, 공지 때문에 밀리는 기록 버튼, 의료진 입력 손실, 내보내기 범위 표시를 먼저 개선한다.
2. **v0.7.0 — 고령 환자 기록 흐름:** 오늘 할 일, 짧은 단계별 사진 기록, 시간대별 복약, 쉬운 오류 복구와 도움 요청을 구현한다.
3. **v0.8.0 — 역할별 업무 관리:** 보조 인력·임상 검토자·연구자·관리자 권한, 업무 대기 목록, 정정·승인·대리 입력 이력을 갖춘다.
4. **v0.9.0 — 재현 가능한 연구 분석:** 기간·대상군·분모·결측·출처를 확정한 자료 스냅샷에서 기술통계와 재현 가능한 자료 추출을 제공하고, 전문 분석은 별도 승인한다.
5. **v0.9.1 — 근거 문헌 검토:** 검색식·검색일·PMID/DOI·근거 구절을 보존하고 사람이 검토한 문헌을 연구 질문과 연결한다.
6. **v1.0.0-rc — 현장 사용성·연구 운영 검증:** 실제 고령자와 직무별 사용자가 핵심 업무를 수행하는지 확인하고 연구 투입 조건을 검증한다.

이 순서는 원래 사업의 **최소 행동으로 일상자료를 수집하고, 실행 가능성 → 타당도 → 예측 연구로 발전한다**는 목적을 유지한다. 4주 기록이나 작은 합성자료만으로 낙상·질병 예측의 임상 성능을 선언하는 단계는 포함하지 않는다. [I1]

## 2. 무엇을 확인했고, 무엇이 아직 확인되지 않았는가

### 2.1 검토 방법과 기준 버전

- 현재 저장소의 기획·화면·자료·API·인증·개발 절차를 읽고 실제 코드와 대조했다. 파일·줄 근거는 부록 A/B에 정리했다.
- 임시 SQLite와 합성자료로 Chromium에서 환자 320/390px, 의료진 1440px 화면을 점검했다. 공개 운영 DB에서 기록을 생성·수정·초기화하지 않았다.
- 같은 날 배포 확인 기록에서 공개 서버 schema5, 최신 화면 파일 18개 일치, 복약 사진 조회 API의 정상 응답이 확인돼 있다. 이번 감사의 화면 계측은 공개 서버가 아닌 동일 커밋의 임시 환경이다.
- 실제 고령 참여자·의사·보조 인력의 사용성 실험, VoiceOver/TalkBack 전체 검증, 실제 AI 정확도 검증은 이번에 수행하지 않았다. 아래 수치는 코드·브라우저 관찰이며 사용자 집단의 성공률이 아니다.

### 2.2 근거의 수준

**D — 이번에 직접 열람:** Apple 공식 HIG 9개 문서, Europe PMC·OpenAlex의 독립 공개 프로젝트 자료, lme4·mice·statsmodels 프로젝트 문서. 접근한 URL과 확인 범위는 부록 C/D에 기록했다. 환자 사용성의 직접 열람 근거는 단일 플랫폼 제공자 지침에 치우쳐 있으며, 한국 고령층의 효과 연구나 최신 체계적 문헌고찰을 직접 검증한 근거는 확보하지 못했다.

**I — 기존 내부 근거:** 현재 코드·계획·과거 임상 검토 문서 및 이번 합성자료 계측. 원래 첨부 문서의 목표는 기존 임상 검토에 남아 있는 인용을 통해 재확인했으며, 이번에 첨부 PDF/DOCX 원문 전체를 다시 읽었다고 주장하지 않는다.

**R — 공식 참고 규격, 최신 원문 재확인 필요:** W3C WCAG/COGA, AHRQ, NIST, FDA, 국내 접근성 기준, EQUATOR 계열 연구 보고지침 등의 공식 사이트는 이 환경에서 접근이 차단됐다. 다른 호스트로 동일 요청을 우회하지 않았다. 규격명·알려진 조항과 공식 확인 링크를 제시하되, 이번 직접 열람 자료나 정식 적합성 판정으로 표시하지 않는다.

따라서 본 보고서는 체계적 문헌고찰·접근성 인증·의료기기 규제 적합성 평가가 아니다. **코드에서 재현된 문제를 해결할 실행계획**이며, 원문 최신판·국내 적용 범위 확인을 첫 승인 단계의 산출물로 포함한다.

## 3. 적용할 개발 기준

### 3.1 고령자를 하나의 동일한 집단으로 보지 않는다

설계 기준은 나이만으로 나누지 않는다. **시력·손 조작·청력·기억 부담·건강 문해력·스마트폰 경험·혼자 사용 가능한 정도·보호자 지원·네트워크 환경**으로 사용 조건을 나눈다. ‘고령이므로 모든 기능을 제한한다’는 방식보다 기본 흐름을 단순하게 만들고 필요한 기능을 단계적으로 펼친다.

- 혼자 사용하는 환자: 큰 글씨, 오늘 할 일, 익숙한 말, 한 화면의 한 가지 결정.
- 도움을 받는 환자: 설명을 듣고 직접 선택할 수 있는 흐름, 중단 후 이어하기, 도움 요청.
- 보호자가 대신 기록하는 경우: 누구의 기록인지와 누가 입력했는지 표시, 위임·범위·철회·충돌 처리.
- 보조 인력: 자료 누락 확인·전화/방문 지원·초안 정리·담당자 전달. 임상 판단을 추측하게 하는 선택지 제거.
- 의사·교수·임상 검토자: 변화·근거·예외·검토 상태를 빠르게 확인하고 결정과 근거를 남김.
- 연구자·통계 담당자: 연구 질문·분석 모집단·변수 정의·결측·재현성·반출 범위를 관리.

### 3.2 웹 접근성 기준과 제품 목표를 분리한다

아래 WCAG 항목은 개발 기준 후보로 사용하는 알려진 조항이다. 공식 최신 원문과 국내 적용 규격은 G0에서 재확인한다. [R1–R4]

직접 확인한 Apple HIG는 글자 확대·VoiceOver·간결한 문장·적절한 피드백·입력 감소·필요 시점의 온보딩을 권장한다. 이번 열람한 HIG의 iOS 제어는 기본44×44pt·최소28×28pt로 표기된다. 이 플랫폼 수치와 웹 CSS px 제품 목표는 같은 규격이 아니다. Apple 문서의 수치를 WCAG 준수 증거로 대체하지 않는다. [D1–D9]

### 3.3 공통 제작 규약에 추가할 내용

새 화면마다 다음 항목을 구현 전에 정의한다: **대상 역할, 하루 업무, 가장 중요한 행동, 기본/확장 정보, 문장·숫자의 의미, 로딩/빈값/실패/오프라인/만료 상태, 닫기·뒤로·재시도, 도움 경로, 접근성, 자료 출처, 권한, 검증 사례**.

공통 글자·색·간격·제어 크기는 한 곳에서 관리하고 화면별 임의 값을 줄인다. 환자·의료진용 공통 셸과 공통 대화상자를 둔다. registry/문서 일치 검사에 더해 실제 화면·보조기술·사용자 과제 검증을 수행한다. 변수 목록의 최신성만으로 사용성 검증을 대신하지 않는다.

## 4. 환자 화면 개선 전략

### 4.1 권고 정보 구조

**홈의 기본 순서:** 환자 문맥 → 의료진 공지 요약 → 오늘 해야 할 일 → 완료한 일 → 도움받기. 현재 사용자의 ‘공지 최상단 노출’ 요구는 유지하되, 제목/핵심1건과 미확인 건수를 먼저 보여 주고 전문·이전 공지는 펼친다. 기관이 정한 중요 공지는 별도 시각 표시하고, 공지를 읽었다는 표시를 내용을 이해했다는 증거로 간주하지 않는다.

**하단 기본 탐색 제안:** ‘오늘 / 내 기록 / 도움·메시지’ 3개를 사용자 실험의 출발안으로 한다. 복약과 식사는 오늘 할 일에서 직접 진입한다. 건강 연결·계정·설정은 도움/설정에서 접근하되, 실제 사용성 평가에서 복약 독립 메뉴가 필요하면4개 대안을 비교한다. 3개가 보편적으로 최적이라는 가정은 하지 않는다. 현재6개 메뉴 변경은 별도의 명세 변경 승인을 받은 뒤 적용한다.

### 4.2 사진·복약 입력의 구체적 개선

1. 촬영 전에 좋은 사진 예시와 ‘약 이름이 보이게’ 같은 한 문장 안내를 제시한다. 파일형식·5MB 제한은 사용자가 변환해야 하는 기술 과제가 되지 않도록 기기별 촬영/리사이즈·HEIC 처리 가능성을 검증한다.
2. 동의 화면에서는 전송 대상·목적·선택권·수동 경로를 읽기 쉬운 문장으로 제시한다. 문구를 줄이기 위해 실제 동의를 자동 체크하거나 알 수 없는 내용을 확인한 것으로 처리하지 않는다.
3. AI 분석 중에는 현재 단계와 기다리는 상태, 취소·재시도·직접 입력을 안내한다. 실제로 계산하지 않은 완료 퍼센트를 표시하지 않는다.
4. 식사량을 확실히 모르면 음식 기록만 남기고 영양량을 ‘산출 불가/확인 대기’로 둘 수 있는 계약을 설계한다. 이를 위해 현재 필수 영양값 저장 계약의 변경이 선행돼야 한다.
5. 약명·함량·회차를 긴 전체 목록에서 매번 찾기보다 지금 보고할 시간대부터 보여 준다. 일괄 ‘모두 먹음’은 약 목록을 제시하고 본인이 확인한 경우만 허용한다. 일부 복용과 기억 안 남의 선택을 같은 수준으로 제공한다.
6. 저장 후에는 큰 완료 표시와 날짜·항목·수정 진입을 제공한다. 짧게 사라지는 알림만으로 완료를 전달하지 않는다. 서버 저장 실패와 저장 후 목록 갱신 실패도 다른 문구로 표현한다.

### 4.3 중단·실수·도움의 설계

- 닫기/뒤로/Escape/새로고침/세션 만료를 공통 규약으로 처리한다. 저장 중 환자·날짜·화면 변경을 막고, 다시 보낼 때 같은 기록이 중복되지 않도록 한다.
- 임시저장은 무조건 localStorage에 사진·건강자료를 남기는 방식으로 구현하지 않는다. 개인 기기와 공용 기기, 보관 만료·삭제·동의·암호화 요구를 검토해 서버 초안 또는 제한적 기기 보관 중 선택한다.
- 통신 끊김에는 ‘휴대폰에만 남음/서버 저장됨/재전송 필요’를 구분한다. 실제 오프라인 대기열이 구현·검증되기 전에는 저장된 것처럼 표현하지 않는다.
- 도움 요청은 전화·지원 안내·사이트 내 메시지 중 기관이 운영할 수 있는 경로를 선택한다. 보조 인력이 연락한 결과는 환자 기록과 별도로 업무 이력에 남긴다.
- 보호자 기능은 별도 계정·위임 대상·입력 범위·기간·철회·입력자 표시가 준비된 뒤 도입한다. 계정 공유나 보호자 기기의 건강자료를 환자 자료로 자동 전송하는 방식은 사용하지 않는다.

## 5. 의료진·보조 인력 화면 개선 전략

### 5.1 기본 화면을 업무 단위로 나눈다

의료진 대시보드의 첫 질문은 ‘수치가 몇 개인가’보다 **누구에게 무엇을 해야 하고, 어떤 자료를 근거로 판단할 수 있는가**여야 한다.

- **오늘 할 일:** 미확인 사진, 답장 대기, 누락 연락, 계획 확인 요청, 맡은 업무의 기한.
- **환자 검토:** 식사·복약·활동·수면을 같은 기간축에서 비교. 원자료·출처·수신 시각·정정·임상 메모로 이동.
- **자료 정리:** 누락·중복 의심·형식 오류·정정 요청을 체크하고 담당자에게 전달.
- **연구 분석:** 승인된 연구 대상군과 자료 스냅샷만 사용. 쉬운 기술통계와 전문가 분석을 구분.
- **근거 문헌:** 연구 질문과 연결된 검색·선별·근거표·검토 이력을 관리.

표의 기본 밀도와 넓게 보기 옵션, 열 선택·정렬·고정, 기간 필터·환자 문맥을 제공한다. 필요한 정보를 숨기지 않으면서 7~10px의 글자로 많은 항목을 압축하는 현재 방식을 개선한다. 소수 환자 데모 속도를 근거로 수백 명·장기자료 성능이 충분하다고 가정하지 않는다.

### 5.2 역할과 승인 권한 제안

아래는 제품 역할의 초안이다. 의료법상 자격·기관 규정·업무 위임은 기관이 확정하며, 직함이나 화면의 모드 선택만으로 권한을 부여하지 않는다. 서버에서 권한과 담당 환자/기관/연구 범위를 검사한다.

| 업무 | 보조 인력 | 임상 검토자 | 연구자·통계 담당 | 운영 관리자 |
|---|---|---|---|---|
| 담당 환자 기록 조회·연락 업무 | 배정 범위 허용 | 배정/기관 범위 | 승인된 가명 연구자료 중심 | 운영에 필요한 최소 범위 |
| 자료 정리·정정 제안 | 초안 작성·이유 첨부 | 검토·승인·반려 | 연구자료 질의·분석 제외 제안 | 자동 임상 승인 없음 |
| 약명·용량·기간·계획 확정 | 확정 불가, 원문 정리·확인 요청 | 기관이 허용한 자격자만 확정 | 연구 역할만으로 변경 불가 | 관리자라는 이유만으로 변경 불가 |
| 공지·메시지 | 승인된 안내문/업무 연락, 임상 문의 전달 | 임상 안내·검토 | 연구 모집/안내 권한 별도 | 템플릿·계정 관리 |
| 통계 | 정해진 완결률·건수 조회 | 임상 기술통계·환자 추이 | 사전 정의 분석·모형 검토 | 시스템 현황 |
| 반출 | 기본 불허 또는 승인된 제한 반출 | 목적·대상·열 범위 확인 | 가명 자료·승인·감사 조건 | 계정/정책 관리, 연구 반출 자동 허용 안 함 |

의사·간호사·영양사 등 임상 직군 내부의 권한도 기관 정책에 따라 분리할 수 있다. 한 사람이 여러 역할을 맡으면 현재 작업 역할과 자료 범위를 분명히 표시하되, 권한 합집합이 의도치 않게 넓어지지 않도록 검사한다.

### 5.3 검토 업무와 자료 정정

업무의 기본 상태는 **새 요청 → 담당 배정 → 검토 중 → 추가 정보 요청/반려 → 완료**로 제안한다. 임상 검토 결과, 자료 품질 검토 결과, 환자의 자기보고 확인은 별도 상태로 저장한다. ‘사진을 봄’이 ‘복용 확인’ 또는 ‘처방 승인’을 의미하지 않아야 한다.

보조 인력의 정정은 `원자료 → 정정 제안 → 임상/자료 책임자 승인 → 적용값`으로 연결한다. 원자료를 조용히 덮어쓰지 않는다. 작성자·역할·변경 전후·사유·적용 기간·승인자·버전을 남기고 동시 수정 충돌을 처리한다. 기존 복약 수정 이력과 사진 snapshot은 이 구조의 출발점으로 보존한다.

경보는 **자료 부족 / 입력 이상 / 기관의 검토 규칙 해당 / 임상 결정**을 구분한다. 현재 규칙 점수는 질병 확률이 아니며, 보조 인력이 ‘규칙 미해당’을 건강 정상으로 읽지 않도록 한다. 담당자·응답기한·재알림·해결 기준이 없는 새 경보를 계속 추가하지 않는다.

## 6. 통계·연구 분석 기능의 구체적 설계

### 6.1 화면보다 먼저 지표와 분석단위를 고정한다

| 지표 | 제안 정의 | 필수 표시·제외 규칙 |
|---|---|---|
| 환자 수 | 선택한 연구/기간의 고유 참여자 N | 관측행 수·일수와 구분. 포함/제외 기준과 분석 집단 기록 |
| 항목별 수집률 | 유효한 항목 관측 수 ÷ 해당 항목의 계획된 관측 기회 | 등록 전·프로토콜상 수집기간 종료/정식 휴지·미대상 기회만 승인 규칙대로 제외. 단순 미보고·추적 탈락을 임의로 분모에서 빼지 않음. 필수 끼니/회차는 프로토콜로 정의 |
| 복약 보고 완결률 | R ÷ D: 응답이 있는 예정 회차 / 분석 대상 예정 회차 | R에는 명시적 기억 안 남 포함, 미보고 제외. D에서 확정 보류·중단·PRN 포함 여부 사전 정의 |
| 예정 회차 대비 복용 보고 비율 | T ÷ D | 미보고가 많으면 낮아질 수 있음을 함께 표시. 객관적 복용 이행률로 이름 붙이지 않음 |
| 알려진 보고 내 복용 비율 | T ÷ K, K=복용+명시적 미복용 | K=0이면 계산 불가. 모름·미보고를 제거한 선택 편향과 D/R/K를 함께 표시 |
| 식사 영양 추정 | 기록된 식사 중 포함 가능한 추정의 합계·분포 | 촬영/분량확인/분석실패·끼니 누락을 표시. 기록되지 않은 끼니를0으로 채우지 않음 |
| 활동·수면 | 환자·일자별 유효값의 분포와 개인 추이 | 값0과 미측정 구분. 기기/자기보고·수면 정의·시간대·수동 우선 규칙 유지 |

각 예정 관측 기회에는 최종 유효 관측을 한 번만 대응해 중복 전송으로 수집률이100%를 넘지 않도록 한다. D는 분석 기준시각까지 예정된 유효 회차이며 미래 회차는 제외한다. T는 각 회차의 최종 유효 수정본에 남은 복용 자기보고 수다. 모든 분모가0이면0% 대신 산출 불가로 표시한다. 추적 탈락 이후 결과의 처리와 중단 관련 분석은 추정대상(estimand)·통계분석계획(SAP)에서 별도로 정의한다.

기존 일일 복약 점수의 `partial=0.5`는 현재 데모의 가중 점수이며 약별 회차 비율과 합치지 않는다. 새 ‘일부 복용’ 구조를 도입하면 어떤 약을 얼마나 보고했는지 정의한 뒤 새로운 지표 버전을 만든다. 명칭을 바꾸는 것만으로 과거 점수의 의미가 달라지지 않는다.

### 6.2 기본 통계와 전문가 분석의 범위

**기본 화면:** 기간·환자군·자료 출처·검토 상태 필터, N/관측 수/계획 분모/결측, 평균·표준편차·중앙값·사분위범위, 분포·개인 추세·수집률을 제공한다. 평균만 보여 주거나 자료가 없는 환자를 자동 제외한 결과만 표시하지 않는다. 변화량의 기준일과 허용 관측창을 명시한다.

**후속 전문가 확장(기본 일정 밖):** 대응된 전후 비교, 환자 내 반복 관측을 고려한 혼합모형/GEE 등은 통계 담당자와 사전 정의한 분석 템플릿으로 제공한다. 환자100명×28일을 독립 표본2,800명처럼 처리하지 않는다. 모형 선택·가정·수렴 실패·효과크기·신뢰구간·다중 비교·공변량·탐색/확증 구분을 기록한다. [D12–D14]

결측은 원인이 확인된 경우만 사유를 코드화한다. 기기 미수신만으로 비착용·권한 거절·건강 악화를 확정하지 않는다. 기본은 결측의 양과 패턴을 보이는 것이며, 평균 대치·직전값 이월·다중대치를 조용히 자동 적용하지 않는다. 다중대치도 가정·포함 변수·반복 수·난수·민감도 분석을 기록한 전문가 절차다. [D13]

앱에서의 상관·전후 차이·임계값 초과는 인과관계나 치료 효과의 증명이 아니다. p값 하나로 임상 중요성을 판정하지 않으며, 작은 표본의 하위군·다수 지표 탐색에는 불확실성을 크게 표시한다.

### 6.3 재현성과 자료 계약 초안

연구 분석은 실시간 화면의 현재값을 계속 바꿔 계산하는 방식 대신 **동결한 자료 스냅샷 + 분석 설정 + 실행 결과**를 보관한다. 제안 필드는 다음과 같다. 아직 DB 스키마 변경으로 승인된 것은 아니다.

- `studyId / datasetSnapshotId / participantPseudonym`: 연구·자료 버전·가명 참여자 연결. 신원 연결표와 분석자료의 접근권한 분리.
- `observedDate / observationAt / intervalStart / intervalEnd / receivedAt / recordedBy / source / deviceSource / timezone`: 일자 집계·관측 구간·정확한 시각과 수신 시각·입력자·출처를 구분. 일별 합계에 존재하지 않는 관측 시각을 임의로 만들지 않음.
- `qualityFlags / missingReason / reviewState / adjudicationVersion`: 실제 확인한 품질·결측·검토·정정 버전.
- `analysisRecipeId / recipeVersion / cohortDefinition / variableDefinitions / denominatorRules`: 같은 결과를 다시 만들기 위한 설정.
- `method / covariates / exclusions / missingDataPolicy / softwareVersion / randomSeed / runId`: 분석 방법과 실행 환경·제외·재현 조건.
- `exportManifest / approvedBy / exportedAt / fields / rowCount / checksum`: 반출 범위·승인·감사·무결성. 사진/자유서술/실명은 기본 연구 반출에서 제외하고 승인된 경우만 별도 처리.

CSV는 ‘현재 선택 환자’인지 ‘전체 대상군’인지, 기간·열·실명 포함 여부·예상 건수를 미리 보여 준다. 가명화는 익명화 보장을 뜻하지 않으며 작은 집단·희귀 조합의 재식별 위험도 기관 정책으로 다룬다. 표준 형식은 장래 FHIR/OMOP 연계를 고려할 수 있으나, 지금 전체 시스템을 그 규격으로 재작성하는 것을 선행조건으로 삼지 않는다.

## 7. 관련 연구자료 검색·검토 기능

권고 흐름은 **질문 만들기 → 검색식 검토 → 문헌 검색 → 중복 제거·선별 → 근거표 → 검토·연결**이다. 임상 질문은 PICO/PECO, 사용성·실행 가능성 질문은 대상·상황·업무·결과 지표 등 알맞은 구조로 작성한다. 모든 질문을 억지로 PICO에 넣지 않는다.

1. PubMed를 의생명 문헌의 주요 검색원 후보로 하고, Europe PMC의 메타데이터/합법적으로 공개된 원문과 OpenAlex의 추가 탐색 기능을 비교한다. 특정 API의 현재 인증·쿼터·비용·라이선스·서비스 수준은 연결 전 실제 확인한다. 이번 작업은 계정 생성이나 실 API 통합까지 진행하지 않았다. [D10–D11, R8]
2. 환자 이름·연락처·자유서술·원본사진을 검색어에 자동 전송하지 않는다. 연구 질문은 최소한의 일반화된 개념으로 만들고 사용자가 검색식을 검토한다.
3. 제목·저자·연도·학술지·PMID/DOI·연구설계·대상·결과·한계·근거 구절·출처 위치·검색일을 표로 보관한다. DOI/PMID 검증, 제공자에서 확인한 철회/정정 상태와 확인일 표시, 같은 논문 중복 제거, 접근 가능한 전문 범위를 관리한다.
4. 제공 범위 밖이거나 확인하지 못한 철회·정정 상태를 “철회 없음”으로 바꾸지 않는다. AI 요약은 근거가 있는 초안이다. 초록만 읽은 문헌은 ‘초록 기반’으로 표시하고, 확보한 초록 또는 본문에 근거하지 않은 표본 수·효과·결론을 생성하지 않는다. 초록에 근거한 정보는 그 범위를 명시한다. 인용 연결이 끊기거나 근거 구절이 없으면 검토 완료로 저장하지 않는다.
5. 보조 인력은 검색·중복 정리·초기 선별·메타데이터 확인을 수행하고, 임상 적용 및 근거 강도 판단은 배정된 검토자가 맡는다. 인용 수를 곧바로 근거 수준으로 표시하지 않는다.
6. 검색식·검색일·데이터원·필터·포함/제외 사유·검토자·내보낸 RIS/BibTeX를 남긴다. PRISMA/STROBE/CONSORT/SPIRIT 등은 연구 유형에 맞는 보고 지침 선택을 돕는 자료이며, 앱 버튼을 만들었다고 연구설계가 적절하거나 보고 지침을 준수했다고 주장하지 않는다. [R7]

문헌 데이터가 외부에서 들어오더라도 이미지 속 문구와 마찬가지로 비신뢰 입력으로 다룬다. 문서에 쓰인 지시를 시스템 명령으로 실행하지 않으며, 링크·파일은 허용된 방식으로 취급한다. 임상 권고나 약물 변경을 문헌 요약에서 자동 적용하지 않는다.

## 8. 버전업 로드맵과 완료 관문

### 9.1 공통 필수 검증 시나리오

- 처음 접속한 환자가 오늘 필요한 기록을 찾고 완료 후 저장 내용을 다시 확인한다.
- 큰 글자·화면 확대·가로 화면·키보드·VoiceOver/TalkBack에서 약·상태·동의·저장·오류를 구별한다.
- 잘못된 사진·흐린 사진·AI 실패·한도 오류·HEIC·큰 파일에서 다음 행동을 설명하고 직접 입력으로 복귀한다.
- 촬영·분석·저장·조회 각각의 지연 중 뒤로/닫기/다른 환자/다른 날짜가 이전 결과를 섞지 않는다.
- 의료진의 계획·공지·메시지·정정·분석 설정을 편집하다 닫아도 입력 보존/포기 확인이 일관된다.
- 보조 인력이 직접 API를 호출해도 계획 확정·임상 검토·다른 기관·승인 없는 반출이 불가능하다.
- 보호자 입력자와 자료 주체가 다르게 남고, 철회 이후에는 접근·입력이 차단된다.
- 미보고/모름/0/분석 실패/기기 미수신을 통계·CSV·화면에서 동일한 의미로 처리한다.
- 같은 스냅샷·설정·소프트웨어 버전·난수 조건에서 분석 결과가 재현된다.
- 사진 당시 보고 snapshot과 이후 정정 상태를 함께 보여 주고, 사진이 실제 복용 증거로 바뀌지 않는다.
- 문헌의 식별자가 실제 문헌과 일치하며 인용 구절·원문 접근 범위·선별 이력이 추적된다.
- 운영 장애 복구에서 승인된 자료 보존·계정·감사 이력을 유지한다. 실제 연구 DB의 초기화 버튼은 데모와 분리한다.

### 9.2 완료 증거의 형식

각 작업은 요구ID → 화면ID → 자료/API 변경 → 코드 위치 → 검증ID → 결과 → 배포 버전을 연결한다. 검증 결과는 `통과 / 실패 / 미실행 / 외부 준비 대기`로 기록한다. 합성자료·모의 AI·시뮬레이터 성공을 실제 환자·실 AI·실기기 성공으로 바꾸어 기록하지 않는다.

## 10. 실제 사용자를 포함한 평가 계획

### 10.1 참여자와 과제

형성평가는 회차마다 고령 환자8~12명, 보호자2~4명, 의사/임상 검토자4~6명, 보조 인력4~6명, 연구/통계 담당자2명 안팎을 모집하는 안을 제안한다. 이는 결함 발견과 설계 개선을 위한 표본 가정이며 충분한 임상 검증 표본 수를 뜻하지 않는다. 기관의 대상자 특성·윤리/연구 판단·모집 가능성에 따라 확정한다.

고령 환자는 스마트폰 경험이 낮은 사용자, 저시력·손 조작 어려움, 혼자/도움받는 사용자, 서로 다른 iPhone/Android를 포함한다. 임의로 인지장애를 진단하거나 특정 연령을 사용 불가 기준으로 삼지 않는다. 사진·기록은 합성자료로 수행하고 관찰·녹화·개인정보 수집 범위를 설명한다.

- 환자 과제: 오늘 식사 기록, 먹은 양 모름, 복약 일부/기억 안 남, 저장 확인·수정, 오류 후 복구, 공지 확인·도움 요청.
- 보조 인력 과제: 누락 연락 대상 찾기, 자료 정정 제안, 미확인 사진 전달, 담당자 변경, 허용되지 않는 임상 작업 구별.
- 임상 검토자 과제: 같은 기간의 변화와 원자료 비교, 사진/복약 확인 요청 처리, 약별 회차와 일일 점수 구별.
- 연구자 과제: 대상군·기간·분모 선택, 결측을 포함한 요약, 분석 재현, 승인된 범위 반출, 관련 문헌 근거 확인.

### 10.2 측정 지표와 제안 통과선

| 측정 | 측정 방법 | 제품 내부 목표안 |

최초 사용(조작 시범 전), 표준 교육 직후, 약1주 후 재사용 결과를 구분한다. 동일인의 여러 과제를 독립된 참여자 수로 합치지 않으며, 보호자/직원 대신 수행은 독립 성공에서 제외한다. 중대 오류0건은 사전 정의 시나리오에서 관찰되지 않았다는 목표이며 위험이0이라는 증명이 아니다.

이 목표들은 문헌이 보장하는 성능이나 현재 달성한 값이 아니다. 작은 표본의90%는 모집단 전체 보장을 뜻하지 않으며, 집단별 n/N·실패 사유·가능하면 불확실성 범위를 보고한다. 평균 성공률이 좋아도 저경험 사용자 집단이 반복 실패하면 개선한다.

## 11. 개발 착수 전에 확정할 결정과 외부 준비

아래 결정은 이번 보고서 제출을 막는 질문이 아니다. **향후 개발 지시를 받은 뒤 G0에서 확정할 의사결정 목록**이다.

1. 연구의 최소 필수 기록: 식사 횟수·복약 대상·보완 항목·관찰 기간·일자 분모·중단 기준.
2. 환자군의 실제 기기·지원 필요 분포, 보호자 입력의 허용 범위와 기관 지원 창구.
3. 보조 인력/임상 검토자/연구자/관리자의 실제 담당 업무, 승인자, 대체 담당, 대응 시간.
4. 실제 연구 인증 방식. 카카오와 건강데이터 실연동은 현재 보류 상태를 유지하며 사용자가 우선순위를 바꾸기 전 자동 재개하지 않는다. 역할 분리는 선택한 인증수단과 독립적으로 설계하되 실제자료 운영에는 적절한 본인·역할 확인이 선행돼야 한다.
5. 연구 변수·주요 결과·참조평가·분석 집단·결측 정책·분석계획을 임상/통계 담당자가 승인하는 절차.
6. PubMed/Europe PMC/OpenAlex 등 실제 선택 서비스의 인증·사용 조건·예산·허용 원문·기관 구독 범위.
7. 실제 연구자료용 영구 DB·백업/복구·접근·감사·보존/삭제 정책. 저장소 render.yaml의 기본 /tmp DB와 공개 demo는 합성자료 검수용 구성으로 취급하고(실제 환경변수·저장 정책은 연구 전 다시 확인), 실제자료 운영의 근거로 삼지 않는다.
8. 접근성 원문 최신판·국내 적용 기준 재확인, 실제 고령자 사용성 시험과 연구기관의 필요한 검토 절차.
