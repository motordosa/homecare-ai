# 부록 A. 환자 화면 상세 감사

작성일: 2026-10-23 KST. 기준 커밋: `4068c3cbf9a7dec9afe99035de13cb8b04d401e5`. 이 문서는 승인 전 개선 제안이며 앱 코드·현재 제작 계약을 수정하지 않았다. 분석은 코드/문서 검토와 **임시 SQLite·합성자료·Chromium 320/390 CSS px 화면 계측**이다. 실제 고령 환자, VoiceOver/TalkBack, 실기기, 200% 텍스트/400% 리플로우 평가를 수행한 결과가 아니다. 외부 기준의 원문·발행기관·법적 지위는 통합 보고서의 근거 자료를 함께 따른다.

## 판단 요약

현재 앱은 주요 메뉴 목적·닫기·회차별 자기보고·미응답 보존·출처 구분의 기본 구조를 이미 갖췄다. 그러나 고령 환자가 혼자 매일 쓰려면 **작은 글자와 낮은 대비, 첫 행동까지 많은 화면 요소, 사진 분석 후 과도한 검토 부담, 통신/인증 중단 회복, 지원자 역할**을 우선 보완해야 한다. 사진과 자동 수집을 늘리는 것만으로는 이 부담이 해결되지 않는다. ‘기록해야 할 업무를 적게 보이고, 잘못된 기록을 쉽게 알아보고 고치며, 도움이 필요한 순간 다른 사람이 적절한 권한으로 도울 수 있는 흐름’이 필요하다.

고령을 장애나 인지저하로 일괄 간주하지 않는다. 연령과 별도로 시력·청력·손 조작·인지/기억·디지털 경험·한국어 건강문해력·기기/통신·보호자 도움 여부를 확인하고 기능을 맞춘다.

## 유지할 기존 강점

- P-SHELL의 일반 서브 X→같은 환자 홈, 입력 dialog X→진입 화면, 진입 버튼 포커스 복귀와 미저장 확인이 구현되어 있다. `public/patient.js:65`, `:72`, `:79`, `:84`, `:800`; `public/patient-screens.js:2`.
- 공통 X는 44×44px이며 하단 탐색 버튼은 320px 폭에서도 약52×54px이다. 메뉴 터치 영역이 모두 작다고 단정해서는 안 된다. `public/patient.css:132`, `:144`.
- 날짜/약/회차별 taken·missed·unknown 및 pending 구분, 이전 보고 이력, 다른 회차 초안 보존이 있다. `public/patient.js:630`, `:647`, `:671`; `lib/medications.mjs:129`.
- 부분 저장은 미입력을 임의의 정상값으로 채우지 않으며, 수동0과 미측정 null을 구분한다. `public/patient.js:490`; `docs/CONTRACTS.md:21`.
- 사진 분석은 동의와 사용자 확인, 환자·사진 결합, 수정번호 충돌·재전송 중복 방지, 의료진 미검토 상태를 갖췄다. `public/patient-medication-photo.js:61`, `:73`; `lib/medication-photos.mjs:31`.
- lang=ko, viewport 확대 제한 없음, skip link, form label/fieldset, native dialog, alert/live status, 차트 대체 설명, prefers-reduced-motion 등을 일부 갖췄다. `public/patient.html:2`, `:5`, `:18`, `:33`, `:77`, `:90`; `public/patient.js:299`; `public/patient.css:1`. 다만 이것만으로 접근성 준수나 고령자 사용성 검증을 완료했다고 볼 수 없다.

## 화면별 개선 항목 20개

우선순위 P0=고령 환자 파일럿 전에 해소할 핵심 접근·자료 정확성·권한 문제, P1=첫 사용과 반복 사용을 크게 줄이는 개선, P2=지원 기능 확장. 장애의 의학적 심각도나 임상 위험 판정을 의미하지 않는다.

### UP-01 — 작은 글자와 정보 위계 (P0, P-SHELL/P-HOME/P-MEAL/P-MED)

- 관찰: CSS 재정의 후에도 하단10px, 출처10px, 도움말11px, 상태11px, 다수 설명12~13px이다. 근거 `public/patient.css:4`, `:144`; 계측 JSON.
- 영향: 시력 저하·작은 화면·눈부심 환경에서 중요한 선택/출처/오류 설명을 놓칠 수 있다.
- 제안: 한글 본문 기본18px, 보조16px, 입력18px, 주요 제목24~28px를 초기 시안 목표로 두고 읽기 쉬운 서체·1.5 이상 행간·문단 여백을 검증한다. ‘글자 크게’ 제어와 브라우저 확대를 같이 제공하고 픽셀 고정 선언을 공통 typography token으로 관리한다.
- 인수: 핵심 흐름의 텍스트100%를 명세 token으로 대조,200%텍스트와400%리플로우에서 잘림/겹침/기능 손실 없음; 긴 한국어 약명과 제목 포함. 작은 보조 글자가 필요하면 이유·예외 승인 기록.

### UP-02 — 낮은 문자 대비 (P0, 전 환자 화면)

- 관찰: 메뉴/출처/상태/도움말의 대표 대비가2.14~3.90:1이다. 일부 선택지 글자도 낮은 대비다. 근거 `public/patient.css:1`, `:4`, `:144`; 계측 JSON.
- 영향: 낮은 시력·백내장·밝은 야외·색 인지 차이에서 활성/비활성 및 보고 상태를 구별하기 어렵다.
- 제안: 기본·선택·오류·링크·포커스 토큰을 재정의한다. 일반 문자4.5:1, 큰 문자3:1 기준을 검증하고 중요한 텍스트는 더 높은 대비의 시안을 비교한다. 색만으로 완료·미응답을 전달하지 않는다.
- 인수: 자동 대비 검사+수동 배경/상태 검수, focus/selected/error/hover 포함. 비활성 컨트롤의 예외를 활성 메뉴의 ‘선택 안 됨’ 글자에 적용하지 않음.

### UP-03 — 6개 메뉴와 불균일한 보조 버튼 (P1, P-SHELL)

- 관찰: 하단6개 고정 메뉴이며 ‘기록하기/새로고침’은38px 높이이다. 근거 `public/patient.html:75`, `public/patient.css:4`, `:144`.
- 영향: 디지털 경험이 적은 사용자는 ‘내 기록/복약/건강 연결’ 목적과 위치를 기억해야 한다. 손 떨림 사용자는 작은 보조 버튼을 누르기 어렵다.
- 제안: 오늘 할 일·기록 보기·도움/메시지 등3~4개 상위 목적 시안을 검증하되 자주 쓰는 복약 진입을 숨기지 않는다. 계정/연결 상세는 ‘더보기’로 정리한다. 터치 목표 최소48×48px, 인접 여백8px를 제품 목표로 비교 검증한다.

### UP-05 — X만 보이는 닫기와 되돌리기 의미 (P1, P-SHELL/모든 입력)

- 관찰: 일반 X는홈, dialog X는진입화면으로 일관되며 aria-label도 있다. 시각적 버튼은 X만 보인다. 근거 `public/patient.html:22`, `:78`, `:87`; `public/patient.js:79`.

- 제안: 공통 동작을 유지하면서 ‘홈으로/닫기’ 짧은 가시 문구를 시안으로 검증한다. 미저장 확인은 ‘계속 작성’과 ‘저장하지 않고 나가기’처럼 결과를 이름으로 설명한다. 단순 뒤로가기에서 불필요하게 모든 내용을 지우지 않도록 복귀 상태를 정의한다.
- 인수: 모든 화면ID의 닫기 목적지가 동일 계약대로 동작하고, 입력 유지/버리기 선택의 의미를 대상자가 설명할 수 있음. 사용자에게 위험한 확정 동작을 기본 포커스로 두지 않음.

### UP-06 — 약 사진 분석 후 확인 부담이 큼 (P0, P-MED-PHOTO)

- 관찰: 파일 선택→포장 확인→외부 전송 동의→분석→후보 읽기→회차 체크→상태 드롭다운→최종 확인→저장. 모든 당일 회차를 렌더링하고 최대24개 선택 허용한다. 근거 `public/patient.html:77`, `:82`, `:84`; `public/patient-medication-photo.js:51`, `:58`, `:73`.
- 영향: 사진이 입력을 줄이기보다 약명/함량/회차 대조 과제를 추가한다. 인지·문해력·시력이 낮은 환자에게 의료적 확인 책임이 과도할 수 있다.
- 제안: ‘언제 약을 드셨나요→이번 회차의 등록 약 확인→복용 상태’의 짧은 단계형 흐름을 비교한다. OCR은 기존 계획의 후보 정렬 보조로 쓰고 불일치/읽기 실패는 ‘의료진 확인 요청’ 대기함으로 보낸다. 외부 전송 동의와 실제 자기보고 확인은 각각 의미를 유지한다. 일괄 taken 기본 선택은 금지하고 사진으로 복용을 증명하지 않는다.
- 인수: 같은 이름/다른 함량·미등록 약·흐린 사진·0후보·다제복용·미복용/모름 사례에서 잘못된 약/회차 확정0. 사용자는 ‘사진 분석’과 ‘내가 먹었다고 보고’를 구별할 수 있어야 함. 단계별 이탈/도움 요청을 측정.

### UP-07 — 사진 형식/용량 실패를 환자가 해결해야 함 (P1, P-MEAL/P-MED-PHOTO)

- 관찰: JPEG/PNG/WebP5MB 제한, HEIC는환자가JPEG변환 안내, 원본 FileReader 전달. 근거 `public/patient.html:80`, `:87`; `public/patient-medication-photo.js:91`, `:94`; `public/patient.js:860`.
- 영향: 최신 휴대폰 기본사진 용량/형식에서 기록을 포기할 수 있다. 약봉투 개인정보 가리기도 수동 부담이다.
- 제안: 촬영/보관함 선택을 명확히 하고 회전·크기 축소·지원 형식 변환·잘림/흐림 안내·가리기 도구를 검토한다. 브라우저가 해독하지 못하는 HEIC는 실제 기기 지원 범위를 확인하고 촬영 재시도/지원 요청 경로를 제공한다. 원본·분석용·저장본/hash 계약을 먼저 변경한다.
- 인수: 실제 iPhone/Android에서 가로·세로·대용량·권한거절·잘못된형식·중도취소를 검증. 실패 원인이 한국어로 보이며 사진 재선택이 처음부터 모든 정보를 다시 입력하게 만들지 않음.

### UP-08 — 식사 기본 선택과 분수·시간 구분 (P0, P-MEAL)

2. 회차별과업: 링크열기→자기화면인지→식사사진1건→식후양변경→약‘모름’보고→사진후보불일치대응→잘못입력한기록수정→의료진에게도움요청. 네트워크실패/뒤로가기/인증만료는본과업뒤낮은위험의합성환경에서시험한다.
3. 측정: 무도움완료율,도움받은완료율,잘못된환자/약/회차/섭취량저장,소요시간중앙값·분포,중도포기,오탭,불안/부담의간단한구두평가,기억해야한정보수,다음날/1주후재사용성. 말로생각하기는어려운사용자에게강요하지않고관찰/짧은사후질문으로보완한다.
4. 1차수정후다른12~15명확인평가를계획한다. 이숫자는문제발견과버전비교를위한실무제안이며대표성/유효성/정확도확증표본이아니다. 핵심행동무도움성공률90%이상과심각한기록오류0을초기출시목표로검토하되모집집단·보조허용범위·분모·신뢰구간을같이보고한다. 실패가남으면인원수만늘려평균으로가리지않고흐름을수정한다.
