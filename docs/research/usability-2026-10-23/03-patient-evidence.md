# 부록 C. 고령자·접근성 근거

조사일: 2026-10-23(한국 시간). 범위: 외부 개발 지침과 제품 적용 원칙. **앱 코드는 변경하지 않았다. 고령 환자 대상 실제 사용성 시험이나 임상 효과 검증을 수행한 결과가 아니다.**

## 1. 근거 수준과 접근 제한

- **직접 확인:** Apple의 공식 Human Interface Guidelines(HIG) 9개 문서 본문. developer.apple.com의 공개 문서 페이지와 그 페이지가 제공하는 공식 JSON 콘텐츠를 읽었다. 제목·업데이트 메타데이터·본문을 직접 대조했다. 최초 Accessibility HTML은 앱 셸이므로 그것만으로 본문을 읽었다고 판단하지 않았고, 같은 공식 사이트의 문서 데이터에서 본문을 확인했다.
- **이번 원문 미검증:** W3C, AHRQ, NIA, CDC, 미국 보건부 Health Literacy Online, PubMed, 국내 웹접근성연구소, Android·Microsoft·NN/g의 각 최초 요청이 환경 프록시의 CONNECT 403으로 차단되었다. 동일 차단 도메인은 재시도하거나 다른 호스트·미러로 우회하지 않았다. 이 자료들은 아래에 ‘원문 미확인 참고 기준/확인 후보’로 표시한다.
- W3C 공식 GitHub에서 공개 저장소·태그·파일 목록 메타데이터만 조회한 적이 있으나, 동일 문서의 본문을 가져오지 않았고 이를 규범 본문 검증으로 계산하지 않았다.
- **적용 한계:** 직접 확인한 근거는 플랫폼 설계 지침이며, 한국 고령환자 연구나 웹 접근성 적합성 평가를 대신하지 않는다. iOS의 pt, Android의 dp, 웹의 CSS px를 같은 수치로 취급하지 않는다. 일반 접근성 조항을 적용한다고 고령자 사용성이 자동으로 입증되는 것도 아니다.
- HTTP 결과와 URL: `patient-source-access.json`, 요약표 `patient-source-access.tsv`. 검증한 공식 문서 데이터와 추출문은 같은 디렉터리의 `apple_*.json/.txt`. 네트워크·계정 설정 변경은 하지 않았다.

## 3. 기준 숫자를 혼동하지 않기

### 직접 읽은 HIG 수치

- Apple Accessibility의 iOS/iPadOS 표는 **기본 제어 크기 44×44pt, 최소 제어 크기 28×28pt**로 되어 있다(이번 읽은 2025-06-09 변경 이력 페이지). 이를 ‘Apple이 모든 상황에서 최소44px를 요구한다’고 쓰지 않는다.
- 같은 문서와 Typography는 iOS/iPadOS 글자 **기본17pt, 최소11pt**, 사용자 글자 확대 **적어도200%**를 권고한다. 이 수치는 일반 플랫폼 지침이며 고령환자 연구의 충분조건이 아니다.
- 44pt/28pt를 웹44px/28px와 물리적으로 같은 크기로 주장하지 않는다. 웹에서는 CSS px·실제 기기의 표시 크기·글자 확대·손동작으로 검증한다.

한국어 웹 접근성 지침(KWCAG)의 적용 버전·인증 요건은 원문 확인 없이 WCAG2.2와 같다고 쓰지 않는다. 국내 제공/연구 환경에 적용할 최신 표준과 기관 요구는 별도 확인 과제로 남긴다.

## 4. HomeCare 고령환자 화면용 제품 기준 제안

아래 숫자는 외부 가이드가 명령하는 값이 아니라 **고령 대상 사용성 시험을 시작하기 위한 제품 목표 초안**이다. 실제 환자의 시각·운동·인지·문해력·기기 특성에 따라 수정한다.

1. **글자와 대비:** 본문/핵심 선택18~20 CSS px, 보조 설명16px 이상을 시작점으로 삼고 큰 글자 설정 제공. 의미를 담은 작은 글자를 늘리는 대신 중요 내용 우선 배치. AA 대비를 기본 검수 목표로 정하고 핵심 복약·오류 내용은 더 높은 가독성으로 평가(E-P01/02).
2. **제어 영역:** 주 작업48~56 CSS px 높이 및 충분한 가로폭, 서로8~12 CSS px 이상 간격을 초기 설계값으로 제안. 작은 체크박스만이 아니라 문장/카드 전체를 선택 영역으로 삼고 선택 상태를 글자·기호로 함께 표시(E-P01/05). 수치 자체가 WCAG 통과 증명은 아니다.
3. **한 번에 한 일:** 홈은 ‘오늘 식사 기록/오늘 약 기록/도움 받기’ 같은 핵심 작업과 완료 상태 중심. 전체 기록·연동 설정·상세통계는 더보기 아래에 두는 방안을 실제 사용자와 시험(E-P01/07). 의도치 않은 의료진 역할 전환은 정상 환자 흐름에서 제거하되 이미 로그인 역할을 다시 추정하지 않음.
4. **장문 대신 단계:** 사진 고르기→읽기 결과/등록 약 확인→복용 여부→저장 확인으로 나누되 현재 위치·이전 단계·취소 의미를 일정하게 유지. 한 화면의 긴 약 회차 체크 목록보다 선택된 약의 다음 회차 중심 흐름을 비교 시험(E-P01/07).
5. **확인 부담을 위험에 맞추기:** 매 회차마다 반복 동의/일반 경고를 쌓지 않고 외부 사진 전송과 실제 복약 보고 확인을 명확히 구별. 데이터 손실·다른 환자 귀속·처방 변경은 강한 확인, 무해한 뒤로 이동은 쉽게 되돌리기(E-P06). 사진의 복용 증거 오인을 막는 핵심 설명은 유지.
6. **쉬운 용어·존중:** 약의 ‘회차’는 ‘오늘 아침8시 약’처럼 생활 맥락으로 설명. ‘초안’은 ‘사진에서 읽은 내용, 확인이 필요해요’. 실제 계획에 없는 시각/약을 임의로 아침/저녁으로 바꾸지는 않는다. 아동용 문체·과장된 칭찬·나이로 능력을 단정하는 표현을 피함(E-P03/07).
7. **지속적인 저장 결과:** ‘저장했어요’와 날짜·약/식사·내용이 다음 화면에도 남게 하고, ‘아직 전송되지 않음/연결되면 재시도/검토 필요’와 구별. 수 초 후 사라지는 토스트만 성공 근거로 사용하지 않음(E-P01/06).
8. **이유와 다음 행동:** 사진 버튼이 비활성인 경우 ‘등록된 약이 없어요. 의료진에게 약 목록을 요청해 주세요’와 도움 경로를 같이 표시. 기술 설정명·모델명·오류코드보다 해결 행동을 먼저 보여줌(E-P06/07).
9. **입력 최소화와 안전한 기본값:** 날짜·확정 계획은 재사용하되 복용·미복용·먹은 양을 자동 선택하지 않는다. 사진/기기 정보는 출처와 처리 단계가 확인될 때만 사용. 사용자가 중단한 선택은 최종 기록으로 저장하지 않음(E-P05).
10. **실행형 첫 교육:** 첫 방문에 보조 인력이 시범을 보인 뒤 환자가 직접 같은 핵심 과제를 수행하고 설명하게 하는 짧은 연습을 제안. 이를 연구 결과로 확정하지 않고 실제 참여자 이해도·독립 수행률로 평가(E-P09; AHRQ teach-back은 이번 원문 미확인).
11. **도움과 대리 입력:** 매 단계 일정한 위치의 도움, 전화/기관 연락(운영 시간·응답 범위), 보호자/직원 대리 입력을 별도 역할과 작성자 출처로 설계. 타인의 계정을 공유하거나 환자의 복용 사실로 자동 귀속하지 않음. 이는 제품·데이터 거버넌스 제안이며 HIG가 대리권한 설계를 직접 규정하지 않음.
12. **실기기 검증:** 320/390/430px, 화면 확대/큰 글자, 세로·가로, 소프트 키보드, VoiceOver/Safari, Android TalkBack/Chrome, 손 떨림/느린 조작 상황을 과제로 검증. 자동 접근성 스캔은 구조 오류를 찾는 보조이며 실제 고령자 시험을 대신하지 않는다(E-P01/02/04).

## 5. 사용자 연구와 판정 기준 제안

- ‘고령자’를 하나의 집단으로 묶지 않는다. 디지털 숙련도, 시각/손동작, 글 읽기 편안함, 인지·기억 어려움, 독거/보호자 도움, 스마트폰 종류를 모집·관찰 변수로 둔다. 나이 구간은 기술통계로 함께 기록하되 임의 기준으로 배제하거나 기능을 강제하지 않는다(E-P03).
- 형성평가는 다양성을 가진 소규모 집단으로 여러 차례 반복하는 설계를 제안한다. 소수 인원의 결함 발견 시험을 임상적 안전성·전체 고령층 대표성·통계적 효과의 입증으로 표현하지 않는다.
- 핵심 과제: 첫 접속, 오늘 식사 사진 선택, 분석 오류에서 수동 입력, 아침 약1회 보고, 저장 결과 확인, 실수 수정, 뒤로가기, 도움 요청, 큰 글자/보조기술 사용. 환자 스스로 수행/설명 가능한지 관찰한다.
- 측정값: 도움 없이 완료, 중요한 오입력, 환자/날짜/약 오귀속, 도움 요청 횟수, 이탈, 저장 성공 오인, 과제시간 중앙값/분포, 사후 이해도. ‘빠르게 누르기’보다 정확한 기록·회복 가능성을 우선한다.
- 제안 릴리스 목표(검증 전 초안): 핵심 과제 독립 완료90% 이상, 관찰된 환자/약 오귀속·미저장 성공 오인0건, 반복되는 중대 차단 결함0건. 모집단·표본크기·실패 처리와 신뢰구간을 같이 제시하고, ‘0건 관찰’을 위험0 증명으로 해석하지 않는다.
- 보호자/보조 인력이 실제로 대신 수행한 과제는 환자 독립 완료에서 제외하고 별도 보조 완료로 집계한다. 연습 직후만이 아니라 며칠 후 반복 사용에서 기억·재진입·네트워크 실패를 확인한다.
