# HomeCare AI 사용자 실행 요청 보고서

작성일: **2026-10-17 KST**. 대상: Android·갤럭시 워치 우선 데모. 이 보고서는 개발자가 수행한 작업과 계정 소유자·기기 사용자가 직접 해야 하는 작업을 구별한다. 최종 검사 수·빌드 결과는 CHANGELOG, 화면 제작 기준은 SCREEN_SPEC, 전송 기준은 SMARTPHONE_SYNC_SPEC에서 확인한다.

## 1. 먼저 알아둘 점

환자 앱은 계속 **모바일 웹**이다. 별도 Android 앱은 휴대폰의 Health Connect 권한으로 걸음·수면을 읽고 웹 서버에 전달하는 작은 연결 앱이다. 갤럭시 워치 자료는 삼성 헬스 등 호환 앱을 통해 폰 Health Connect에 공유되어 있어야 한다. 워치 값을 웹에서 직접 읽거나 폰·워치 합계를 다시 더하지 않는다.

**Health Connect 연동 자체에는 OpenAI 키, 유료 건강 API 계약, 별도 DB 계정이 필요하지 않다.** 먼저 필요한 것은 테스트 폰에 앱 설치, 건강 저장소의 자료 공유, 해당 항목 읽기 권한이다. 사진 AI 키는 별개의 선택 항목이다.

## 2. 현재 개발 범위

| 항목 | 이번 구현·검증 범위 | 남은 외부 확인 |
|---|---|---|
| 환자 화면 | 화면별 명세·공통 상단 X·역할 전환 분리·미저장 확인·저장 중 이동 잠금 | 새 웹 버전 공개 배포 후 실제 사용성 |
| 서버 수신 | 환자 토큰·preflight·부분 항목·항목별 revision·재전송/폐기·수동 입력 우선 | 새 서버 배포·기기에서 실제 HTTPS 통신 |
| Android 연결 앱 | 일부 권한만 수집·암호화 큐·철회 항목 전송 차단·WorkManager·환자 웹 열기 | 설치·실제 권한/삼성 공유/OS 절전 |
| 검증 | 임시 DB·브라우저·실제 Kotlin 단위검사·APK/lint; 결과는 CHANGELOG | 기종별 실기기 결과는 미실행 |

소스 저장/자동검사/APK 빌드/공개 배포/실제 워치 수집은 각각 다른 완료 단계다. 이 보고서만으로 실제 기기 연동 완료를 뜻하지 않는다.

## 3. 지금 필요한 사용자 작업

### U-01 — Render에서 최신 웹·서버 배포 (우선순위1)

필요 이유: 이 세션에는 Render 관리 화면을 조작하는 연결이나 사용 가능한 관리 API 인증이 없다. GitHub에 코드가 반영되어도 기존 서비스는 자동 배포가 꺼져 있어 갱신되지 않는다.

수행 방법:

1. https://dashboard.render.com 에 로그인하고 기존 `homecare-ai-demo` 서비스를 연다. 새 서비스·유료 DB를 만들지 않는다.
2. 보존할 가상 기록이 있으면 먼저 내보낸다. 무료 서비스의 재배포는 DB/사진을 잃을 수 있다. CSV는 전체 복원본이 아니다.
3. **Manual Deploy → Deploy latest commit**을 누르고 Live가 될 때까지 기다린다.
4. https://homecare-ai-demo.onrender.com/api/health 에서 `ok:true`, `storage:"sqlite"`, **schemaVersion:3**을 확인한다.
5. 환자 서브 화면의 우상단 X와 이용 안내의 역할 전환 구역을 확인한다. 캐시된 화면이면 새로고침한다.

완료 기준: 최신 배포 커밋/Live/schema3와 공통 탐색 동작. 알려줄 결과: 배포 커밋 번호, 성공/오류, 오류가 있으면 비밀값을 가린 로그 끝부분. 비밀번호·Render API 토큰을 채팅에 보낼 필요가 없다.

### U-02 — Android 개발용 연결 앱 설치 (우선순위2)

필요 이유: 개발 환경에 사용자의 휴대폰·워치가 연결되어 있지 않아 설치·권한 동의·설정 변경을 대신 할 수 없다.

산출물: Android 앱 ID `ai.homecare.connector`, versionCode2 / `0.2.0-unverified`. 최신 APK·서명·SHA256은 integrations/android/README.md와 최종 전달 링크를 확인한다. 개발용 서명이며 Play 스토어 운영 배포본이 아니다.

1. 먼저 U-01을 완료한다. 새 앱은 부분 권한 수신을 지원하지 않는 이전 서버에 자료를 보내지 않는다.
2. 승인된 Android 테스트 폰에 APK를 설치한다. 기존 설치본과 서명 키가 다르면 덮어쓰기가 실패할 수 있으며, 제거 후 재설치는 로컬 연결·대기 자료를 잃는다. 기존 연결이 필요하면 먼저 상황을 확인한다.
3. 개발 PC와 USB 디버깅을 사용하는 경우 `adb install -r app-debug.apk`로 설치할 수 있다. 폰에서 직접 설치하면 운영체제가 해당 다운로드 앱의 설치 허용을 요청할 수 있다.

완료 기준: 앱 실행과 버전 확인. 알려줄 결과: 휴대폰 모델·Android/One UI 버전, 워치 모델·OS 버전, 앱 설치 성공/실패 메시지. 기기 일련번호·계정 ID는 필요 없다.

### U-03 — Health Connect/삼성 헬스 공유·읽기 허용 (우선순위3)

1. 테스트 폰에서 Health Connect가 제공되는지 확인한다. Android14 이상은 시스템 설정에 통합될 수 있고, 이전 지원 기기는 제공자 앱 설치/업데이트가 필요할 수 있다. 앱의 **Health Connect 설정 / 설치 확인**을 이용한다.
2. 갤럭시 워치→폰 삼성 헬스 동기화와 삼성 헬스→Health Connect의 해당 자료 공유를 확인한다. 메뉴 이름·공유 가능 항목은 기종/버전에 따라 달라 실제 화면에서 확인해야 한다.
3. 개발용 시험 환자 웹의 **건강 연결 → 연결 프로그램용 코드 준비**에서 Android 연결 코드를 만든다. 서버 주소·환자 이름·정확한 환자 ID를 대조한다.
4. 연결 앱에 origin(주소의 도메인까지만)·환자 ID·토큰을 입력하고 자료 주체/시험용 확인을 거쳐 저장한다. 환자 이름을 ID 대신 넣지 않는다. 토큰은 채팅·문서·로그로 보내지 않는다.
5. **걸음 수·수면 읽기 권한 선택**에서 시험 항목을 허용한다. 걸음 수만 허용해도 된다. 미허용 항목은 전송하지 않으며 기존 서버 값을 지우지 않는다.
6. **최근7일 동기화**를 누른다. 권한을 허용한 것과 실제 공유 자료가 있는 것은 다르므로 자료0일이면 공유·원기록을 확인한다.
7. **같은 환자의 웹 기록 열기**로 출처와 최근 수신을 확인한다. 웹의 직접 입력값이 있으면 우선 표시되므로 그 값과 기기 수신을 구별한다.

공개 로그인 없는 데모에는 가상 시험 자료만 사용한다. Health Connect 시험 자료는 Android 공식 health-samples/테스트 도구 등으로 준비할 수 있다. 실제 환자/연구 자료나 식별 가능한 개인 건강자료를 공개 데모에 연결하지 않는다. 실제 워치 원자료를 대조하는 단계는 승인된 시험자료와 접근이 제한된 검증 서버에서 진행한다.

완료 기준: 동일 환자의 앱 수신 확인과 웹의 날짜·단위·출처 일치. 알려줄 결과: 아래 검증표의 성공/실패, 기종/버전, 오류 문구. 토큰·개인 건강기록·식별정보 사진은 보내지 않는다.

### U-04 — 자동 동기화와 실기기 검증 (U-03 이후)

앱에서 별도 백그라운드 권한을 허용하고 **백그라운드 자동 동기화 켜기**를 선택한다. 미지원 기기는 앱을 열어 수동 동기화한다. WorkManager의 최소15분 주기는 실시간·정시 수신 보장이 아니다. 강제 종료/절전/오프라인/워치 공유 지연을 각각 확인해야 한다.

| 검증 사례 | 기대 결과 | 사용자 결과 |
|---|---|---|
| 걸음만 허용 | 걸음 수 전송, 기존 수면 보존 | 미실행 |
| 수면만 허용 | 수면 전송, 기존 걸음 수 보존 | 미실행 |
| 둘 다 허용 | 같은 서울 날짜·단위로 수신, 폰/워치 중복 합산 없음 | 미실행 |
| 한 권한 철회 | 해당 항목 미전송, 포함된 대기배치 폐기 후 새 허용 항목 집계 | 미실행 |
| 권한 모두 철회 | 전송 중단·기존 웹 자료 보존·자동작업 중지 | 미실행 |
| 오프라인→복귀 | 허용된 동일 배치 재시도로 중복 생성 없음 | 미실행 |
| 수면 자정/낮잠/중복 | 실제 알려진 수면 단계 합집합, 세션 전체 시간을 대체하지 않음 | 미실행 |
| 원자료 수정·삭제 | 최근7일 재집계에서 항목별 최신값/null 반영 | 미실행 |
| 서버 토큰 폐기/재배포 초기화 | 401 안내, 웹에서 새 토큰 발급 후 재연결 | 미실행 |
| 웹에서 다른 연결 생성 | 이전 앱은 미선택 연결 안내 후 전송 중단 | 미실행 |
| 잠금·절전·재부팅 | 실제 지연 측정, 성공 수신 전 연결 완료로 오인하지 않음 | 미실행 |

## 4. 계정·API 작업의 필요 여부

| 항목 | 지금 필요한가 | 소유자가 해야 할 작업 |
|---|---|---|
| Health Connect API 키 | **필요 없음** | 기기 읽기 권한·자료 공유 허용 |
| Samsung 개발자 SDK 키 | 현재 경로에는 필요 없음 | 직접 Samsung SDK를 쓰는 후속 경로 채택 시 정책/계정/심사 별도 확인 |
| 별도 DB 계정 | 현재 데모에는 필요 없음 | 연구 전환 때 영구 DB/백업·복원·권한 체계 결정 |
| 사진 AI API 키 | 사진 AI를 사용할 때만 | Render Environment에 HOMECARE_VISION_API_KEY 및 VISION_ENABLED=true, VISION_MODEL 설정. 별도 사용료 확인. 채팅/Git 입력 금지 |
| Google Play 개발자 계정·심사 | APK 직접 개발시험에는 불필요 | 스토어 배포 시 기관 명의·서명키·개인정보 안내·건강 권한 선언/심사를 소유자가 처리 |
| iPhone/Apple Watch | 현재 우선순위 아님 | 후속 단계에서 Apple 개발 환경·기기·서명/배포 계정 준비 |

## 5. 연구 투입 전 별도 결정

인증/역할별 접근권한, 연구 동의·IRB/기관 승인, 영구 DB/사진 저장, 백업·복원, 보존·삭제·감사 정책, 기종별 검증과 실제 식사 AI 정확도를 별도 완성해야 한다. 이는 DB 초기화만으로 완료되지 않는다. 이번 외부 작업 요청은 우선 데모 설치·연동 검증을 위한 것이며 이 연구 전환 항목을 모두 완료했다고 보지 않는다.
